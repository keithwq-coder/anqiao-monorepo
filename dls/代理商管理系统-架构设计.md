## 〇、产品定位与核心原则

**原则 1 · 面向心理，不面向管理**：代理商进入系统心理上不接受"被管理"。合作方侧不叫管理系统/CRM，定位"生意工作台"；"管理"只存在于公司内部后台。

**原则 2 · 双端分离**：
```
┌─ 合作方小程序（代理/经销/合伙人）── 做"生意" ─┐
│   订货发货 · 对账返利 · 分销 · 客户报备         │
├─ 公司管理后台（销售部/风控/财务）── 做"管理" ──┤
│   审核签约 · 结算返利 · 考核 · 区域互斥 · 规则配置│
└──────────────────────────────────────────────┘
```

**原则 3 · 规则即数据（本次新增，核心）**：
档位、价盘阶梯、返利比例、保证金、承诺量、保护期、区域分级、价格线、禁用词——**全部是管理后台可编辑的配置数据，代码是通用引擎，不硬编码**。配置**版本化 + 带生效起止日期**：政策会变（质保 12→24 个月、0730 修订、手册 v2→v3），对账/返利计算必须取"当时生效"的那一版规则，不能用今天改过的数。

**原则 4 · 裂变暂缓**：分销裂变（引荐/两级收益）**另说**，移出首版范围，不阻塞核心。

## 一、目标与边界

**目标**：小程序为载体，代理商在"生意工作台"完成订货、发货、对账、分销、报备；公司后台做审核、结算、考核、秩序管控与规则配置。所有业务数字由后台配置驱动。

**首版不做**：真实物流集成（状态由后台更新+订阅消息）；C 端零售；机构 CRM（`crm/` 域）；裂变/引荐（另说）。

## 三、关键业务不变量

1. **区域互斥**：同一地级市内，地级市代理与区县代理互斥。
2. **返利基数 = 实际回款额**（非开票/进货额），到账方计入。
3. **回款才计业绩，铺货不计**。
4. **统一价盘**：供货 1,380 起（3 档阶梯），批出 ≥1,380；零售控价 1,980、B 端 1,680、备案 1,580（单次一笔）。
5. **多重身份就高原则**：同一主体多身份、同一笔交易收益按就高，不重复计取。
6. **报备归属 = 首次报备时间戳**；保护期零售 90 日 / 机构 12 个月（可延 ≤6 月）。
7. **先款后货**（月结客户在额度账期内例外）。
8. **合规红线**：对外统一"精准健康监测"，严禁"医疗级/诊断/治疗"。
9. **规则取历史版本**：所有计算引用"交易发生时生效"的规则版本。

## 四、领域模型

### 4.1 业务聚合

| 聚合 | 关键属性 | 关键行为 |
|---|---|---|
| Party（合作方） | 名称、信用代码/身份证、资质、微信 openid/手机号 | 多重身份绑定 |
| AgentProfile（代理商档案） | party_id、档位(区县/地级市)、区域、年度承诺、季度分解值 | 生命周期状态机 |
| Agreement（协议） | 区域/档位/承诺/保证金/首批货款/有效期 | 签约/续签/解除 |
| Region（区域） | 层级、等级(S/A/B/C)、占用状态 | 互斥约束 |
| Deposit（保证金/首批货款） | 类型、金额、减免延期、退还 | 缴纳/抵扣/退还 |
| Order（订货单） | 产品/数量/单价(按阶梯)/收货地址/状态 | 先款后货流转 |
| Payment（回款） | 金额、到账时间、关联订单 | 计业绩与返利基数 |
| Rebate（返利） | 类型、比例、基数、结算状态 | 季度结算、货款抵扣 |
| CustomerRegistration（报备） | 客户信息、时间戳、保护期 | 归属裁决（小程序录入） |
| Assessment（考核） | 季度回款 vs 分解值 | 整改/缩小区域/退出 |

### 4.2 规则配置域（新增 · 原则 3 的落地）

`[PROPOSAL]` 所有业务数字进配置表，代码零硬编码：

| 配置表 | 内容 | 版本化字段 |
|---|---|---|
| channel_tier | 代理商两档 / 经销商 3 档位（角色、档位码、名称、承诺量、保证金、首批货款、返利上限） | 生效起止、版本 |
| price_ladder | 3 档价盘阶梯（产品、档位、采购量区间、单价） | 生效起止、版本 |
| price_line | 价格线（标价/建议零售/控价/B端/备案，按产品） | 生效起止、版本 |
| rebate_rule | 返利规则（角色、4 类返利、比例、触发条件、结算方式） | 生效起止、版本 |
| deposit_rule | 保证金/首批货款标准（档位 → 金额、可减免/延期） | 生效起止、版本 |
| protection_policy | 报备保护期（客户类型 → 天数、可延天数） | 生效起止、版本 |
| region_grade | 区域分级 S/A/B/C（等级 → 定义/阈值） | 生效起止、版本 |
| banned_term | 合规禁用词（医疗级/诊断/治疗…） | 生效起止、版本 |

**版本化意义**：订单单价取下单时 `price_ladder` 生效版；返利结算取该季度 `rebate_rule` 生效版；保护期取报备时 `protection_policy` 生效版。后台改规则 = 新增一个带新生效期的版本，历史记录不可变。

### 4.3 代理商生命周期状态机

```
意向 → 资质审核中 → 待签约 → 已签约(试销期·3月) → 转正(区域保护激活)
                                          ↘ 试销失败 → 协议解除(退保证金/货款)
转正后: 正常 →(连续两季不达标/违约)→ 整改 → 缩小区域 → 退出
        正常 →(主动退出·提前30天)→ 退出
        正常 →(违约三档)→ 终止(扣保证金)
```

### 4.4 返利引擎（纯函数核心）

4 类返利（代理最高 7%）：季度回款 3% + 年度达标 2% + 市场秩序 1% + 过程指标 1%；基数=实际回款额，季度结算货款抵扣。实现为无副作用 `rebate_calculator`，输入含"规则版本快照"，配金样本对账测试。

```
┌ 合作方小程序（微信原生 / uni-app）──────────────┐

│   订阅消息：发货通知 / 返利到账 / 考核提醒         │

               │ HTTPS JSON（微信合法域名白名单）
┌──────────────▼──────────────────────────────────┐
│ DLS API 后端（FastAPI，复用 crm 的 auth/policy 模式）│
│   channel/domain · application(返利引擎) · policy  │
│   channel/persistence(PostgreSQL+Alembic) · web    │
└──────────────┬──────────────────────────────────┘
               │
┌──────────────▼──────────────────────────────────┐
│ 公司管理后台（Jinja2 或轻 Vue，账号密码+Argon2id）  │
│   审核签约 · 返利结算 · 考核 · 区域互斥 · 规则配置   │
└──────────────────────────────────────────────────┘
```

- 后端复用 crm 模式：身份/会话/CSRF/脱敏投影照搬；合作方侧用微信登录，公司侧账号密码。
- **微信支付（已裁决 B）**：小程序统一下单（JSAPI）→ 支付回调验签 → 自动生成回款记录 → 微信账单自动核对；返利以"货款抵扣"发放（额度冲抵下单应付额），保证金/首批货款/退货退款走"原路退回"。
- 上线前置：HTTPS + 已备案域名 + 微信合法域名白名单 + **企业主体认证 + 微信支付商户号（未注册，待办）**。
