# DLS 仓库操作契约（AGENTS.md）

权威契约：任何 AI 工具/模型进入本仓库，先读本文件。

## 1. 方法学总纲

> **进入本仓库先读 `项目约束.md`（反幻觉/反自说自话的最高权威），再读本文件。**

- **所有功能 spec-first**：无 SPEC 不得写应用代码。想法先进 inbox，经 draft → review → approved 后方可实现。
- **重要任务 TDD**：涉及"钱"的确定性计算，先写失败测试（金样本断言），再实现，后跑绿。
- **整体 SDD**：`idea → inbox → draft → review → approved → task → 实现 → 验证 → 验收/废弃`。

## 2. SDD 状态机

```text
00-inbox（原始想法，可矛盾）
  → 10-draft（工作草案，不授权代码）
  → 20-review（内部完成，待产品方决策）
  → 30-approved（唯一可授权实现的 SPEC）
  → 90-deprecated（已被取代）
```

应用代码可改，仅当全部满足：
1. 目标行为被一条 `30-approved` SPEC 覆盖；
2. 存在一个激活 task，指明 SPEC、范围、归属文件、验证步骤；
3. 产品方明确授权该 task。

**与 crm 的区别**：不设"完整 SPEC 基线冻结"重门——单条 SPEC 批准即可进入实现，适合渠道业务快速迭代节奏。

## 3. TDD 判定（重要任务清单）

**必须 TDD（金样本先行）**：

| 模块 | 金样本来源 |
|---|---|
| 返利引擎（4 类返利、上限 7%/4%、基数=实际回款额） | `Phase1-规则配置与返利引擎规格.md` 第 3.4 节 |
| 价盘阶梯（1380/1280/1180，>1600 面议禁止自动出价） | 同上 |
| 区域互斥（同地级市 地级市代理/区县代理互斥） | 手册 v3 第十三条 |
| 支付抵扣/退款（抵扣退额度、实付退现金） | 架构设计 v3 |
| 报备归属裁决（首次报备时间戳） | 手册 v3 第二十九/三十条 |
| 考核判定（连续两季不达标触发） | 手册 v3 第二十六条 |

**不强制 TDD**：纯展示页、CRUD 表单、文案、管理后台样式。

## 4. 证据纪律（反幻觉）

- 标签：`[VERIFIED]` 已核实 / `[INFERENCE]` 推理 / `[PROPOSAL]` 建议 / `[UNKNOWN]` 未知。
- 引用路径与命令；不编造业务规则、测试结果、API 行为。
- 测试、迁移、部署"通过"必须是真跑过，静态检查 ≠ 测试 ≠ 生产验收。

## 5. 目录结构

├── docs/

## 6. 安全边界

- 不打印/存储密钥；运行时走环境变量。
- 生产部署、真实数据、支付、退款、外部发送前须显式确认。
- 微信支付回调：验签失败拒收、幂等处理、退款金额 ≤ 实付。

## 7. 完成报告

每次完成报告必须：`Status` / `Scope` / `Evidence`（真跑过的命令与结果）/ `Not verified` / `Decisions needed`。

## 8. 双角色 md 编排

- 架构师 = deepseek-v4-pro（写 SPEC / 拆 TASK / 审核验收 / 决策）；实现者 = v4-flash（读卡实现 / 写证据）。
- md 文档是唯一共享记忆；协议详见 `docs/governance/ORCHESTRATION.md`。
- 架构师只写规格与裁决，不替实现者写代码；审核独立复核，不信任实现者自述。
