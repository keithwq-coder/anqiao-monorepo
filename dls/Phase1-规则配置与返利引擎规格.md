# DLS · Phase 1 规格 · 规则配置域 + 返利引擎 + 支付抵扣

- 角色：架构师
- 日期：2026-08-13
- 状态：**规格草案 · 可评审**（不含业务代码实现）
- 前置：业务口径已全部裁决（代理商两档 / 经销商 3 档位 / 价盘阶梯共享 / 报备=小程序 / 支付=微信直付 / 裂变另说）

---

## 一、设计前提

1. **规则即数据**：档位、价盘、返利、保证金、保护期、区域分级、价格线、禁用词，全部是管理后台可编辑的配置数据，代码零硬编码。
2. **版本化 + 生效期**：每条规则带 `effective_from` / `effective_to`，改规则 = 关闭旧版本（写 `effective_to`）+ 插入新版本，**永不在原记录上改**。历史交易对账时按"交易发生时生效的版本"取值。
3. **返利 = 货款抵扣**：无现金发放，结算后计入"可用抵扣额度"，下单时冲抵应付额。

## 二、规则配置表结构

### 2.1 通用版本化字段（所有配置表共有）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID | 主键 |
| effective_from | datetime(tz) | 生效开始（含） |
| effective_to | datetime(tz) \| null | 生效结束（null = 当前有效） |
| version | int | 递增版本号 |
| status | enum | draft / active / superseded |
| created_at / updated_at | datetime(tz) | 审计 |

`[PROPOSAL]` 查询当前规则 = `effective_from <= now AND (effective_to IS NULL OR now < effective_to) AND status='active'`。同一规则同一时刻至多一条 active。

### 2.2 agent_tier（代理商档位 · 两档）

| 字段 | 说明 | 区县代理 | 地级市代理 |
|---|---|---|---|
| tier_code | 档位码 | county | city |
| tier_name | 名称 | 区县代理 | 地级市代理 |
| annual_commitment | 年度回款承诺（元） | 500,000 | 1,000,000 |
| deposit_std | 保证金标准（元，可减免/延期） | 50,000 | 100,000 |
| first_purchase | 首批货款（加盟费性质，全额抵扣） | 30,000 | 40,000 |
| rebate_cap_rate | 返利上限 | 0.07 | 0.07 |
| max_region_grade | 可申请区域等级上限 | （据手册） | （据手册） |
| trial_days | 试销期（天） | 90 | 90 |

### 2.3 price_ladder（价盘阶梯 · 3 档，代理/经销共享）

| 字段 | 说明 | 示例 |
|---|---|---|
| product_code | 产品 | ZQ-SH100 |
| ladder_tier | 档位序号 | 1 / 2 / 3 |
| monthly_qty_min | 月累计采购量下限（含） | 0 / 200 / 700 |
| monthly_qty_max | 月累计采购量上限（不含） | 200 / 700 / 1600 |
| unit_price | 单价（元/台） | 1380 / 1280 / 1180 |
| is_negotiable | 是否面议（>1600） | false / false / false（第 4 档面议另行标记） |

`[PROPOSAL]` "＞1,600 面议"建模为 `monthly_qty_min=1600, monthly_qty_max=null, is_negotiable=true`，下单时单价置空、标记"待人工核价"，禁止自动出价。

### 2.4 price_line（价格线 · 按产品）

| 产品 | 标价 | 建议零售 | 零售控价 | B端底线 | 备案价 |
|---|---|---|---|---|---|
| ZQ-SH100 | 4,980 | 2,480 | 1,980 | 1,680 | 1,580 |
| ZQ-D100 | 980 | — | 980 | 880 | — |

字段：`product_code, line_type(标价/建议零售/控价/B端/备案), amount`。备案价**单次仅限一笔**，由后台审批标记，不是常驻价格。

### 2.5 rebate_rule（返利规则 · 按角色）

| 角色 | 返利类型 | 比例 | 触发条件 | 结算方式 |
|---|---|---|---|---|
| agent | 季度回款 | 3% | 季度回款 ≥ 季度分解值 | 季度·货款抵扣 |
| agent | 年度达标 | 2% | 年度回款 ≥ 年度承诺 | 年度·货款抵扣 |
| agent | 市场秩序 | 1% | 当季无窜货+无低价投诉 | 季度·货款抵扣 |
| agent | 过程指标 | 1% | 当季完成培训+数据上传+报备 | 季度·货款抵扣 |
| dealer | 季度回款 | 3% | 季度回款 ≥ 分解值 | 季度·货款抵扣 |
| dealer | 市场秩序 | 1% | 当季无窜货+无低价投诉 | 季度·货款抵扣 |

字段：`role, rebate_type, rate, trigger_condition, settle_period, settle_method`。

### 2.6 deposit_rule（保证金/首批货款标准）

经销商保证金 5,000（市场秩序基金性质）；代理商保证金/首批货款已在 `agent_tier`。字段：`role, deposit_type(保证金/首批货款), amount, refundable, reducible, deferrable`。

### 2.7 protection_policy（报备保护期）

| 客户类型 | 保护期天数 | 可延天数 |
|---|---|---|
| 零售/小单 | 90 | 0 |
| 机构/政企集采 | 365 | 180 |

字段：`customer_type, protection_days, extendable_days, renewal_condition`。

### 2.8 region_grade（区域分级 S/A/B/C）

字段：`grade(S/A/B/C), definition(等级定义/阈值)`。区域分级决定代理商可申请保护的权限上限。

### 2.9 banned_term（合规禁用词）

字段：`term(医疗级/诊断/治疗/医疗器械(产品级)…), scope(对外文案/报备备注/订单备注)`。报备与订单备注字段做禁用词扫描。

## 三、返利引擎规格（rebate_calculator · 纯函数）

### 3.1 口径裁决注记

`[VERIFIED]` 手册 v3 第二十一条写"进货额"、第二十二条写"实际回款额"，二者字面冲突；知识卡片 `统一价盘` 明确"**返利基数 = 实际回款额（非开票额/进货额）**"。**本引擎以实际回款额为基数**。

### 3.2 输入

```
{
  role: agent | dealer,
  rule_snapshot: 该季度生效的 rebate_rule 快照,
  agent_tier: agent_tier 快照（仅 agent）,
  annual_commitment: 年度承诺（元）,
  quarter_plan: 季度分解值（元，= annual_commitment / 4）,
  quarter_paid: 当季实际回款额（元）,
  annual_paid: 年初至今实际回款额（元）,
  compliance: { 窜货: bool, 低价投诉: bool },
  process_metrics: { 培训: bool, 数据上传: bool, 客户报备: bool },
  settle_period: 季度 | 年度,
}
```

### 3.3 计算规则

| 返利类型 | 公式 | 触发 |
|---|---|---|
| 季度回款 | rate × quarter_paid | quarter_paid ≥ quarter_plan |
| 年度达标 | rate × annual_paid | annual_paid ≥ annual_commitment（仅年度结算） |
| 市场秩序 | rate × quarter_paid | 无窜货 AND 无低价投诉 |
| 过程指标 | rate × quarter_paid | 培训 AND 数据上传 AND 报备（仅 agent） |

- 总额 = Σ 触发项；**总额 > rebate_cap_rate × 当期回款 → 封顶至上限**（代理 7%、经销 4%）。
- 季度结算只发季度类（季度回款 + 市场秩序 + 过程指标）；年度达标返利只在年末结算。

### 3.4 金样本对账用例（单元测试断言）

**代理 · 区县代理**（承诺 50 万，季度分解 12.5 万，上限 7%）

| 场景 | 输入 | 期望输出 |
|---|---|---|
| A 全达标 | Q1 回款 15万，无违规，过程指标全完成 | 季度回款 4,500 + 秩序 1,500 + 过程 1,500 = **7,500（5%）** |
| B 回款不达标 | Q1 回款 10万，无违规，过程完成 | 季度回款 0 + 秩序 1,000 + 过程 1,000 = **2,000（2%）** |
| C 违规 | Q1 回款 15万，有窜货 | 市场秩序 0（全扣）；情节严重 → 当季全部返利 0 |
| D 年度达标 | 全年回款 55万 ≥ 50万 | 年度达标返利 = 2% × 550,000 = **11,000** |

**经销商**（上限 4%）

| 场景 | 输入 | 期望输出 |
|---|---|---|
| E | Q 回款 20万，无违规 | 季度 3%×20万=6,000 + 秩序 1%×20万=2,000 = **8,000（4%）** |

**价盘阶梯**（纯查表，非引擎计算）

| 月累计采购量 | 单价 |
|---|---|
| 150 台 | 1,380 |
| 500 台 | 1,280 |
| 900 台 | 1,180 |
| 1,800 台 | 面议（待人工核价，禁止自动出价） |

### 3.5 结算与抵扣

1. 季度结束后 15 个工作日内，后台触发结算 → 引擎按当季规则快照计算 → 生成 `rebate` 记录（待核）。
2. 财务确认 → 计入代理商"可用抵扣额度"（rebate_balance）。
3. 下单时：应付额 = 单价×数量；可抵扣额 = min(rebate_balance, 应付额)；**微信实付 = 应付额 − 抵扣额**。
4. 抵扣使用扣减 rebate_balance，生成抵扣流水（不可逆）。

## 四、微信支付与对账集成点

| 环节 | 动作 | 关键约束 |
|---|---|---|
| 统一下单 | JSAPI 下单，金额 = 应付 − 抵扣 | 金额 > 0 才调支付；全抵扣则免支付直记回款 |
| 支付回调 | 验签 → 幂等 → 订单状态更新 + 生成 Payment | 回调幂等（重复通知不重复入账） |
| 自动对账 | 下载微信交易账单 → 与本地 Payment 核对 | 差异进入"对账异常"待人工 |
| 退款 | 保证金/首批货款/退货 → 原路退回 | 退款金额 ≤ 实付；抵扣部分退回到 rebate_balance 而非现金 |
| 返利抵扣 | 下单时冲抵 | 抵扣不触发微信支付，记抵扣流水 |

`[UNKNOWN]` 退款时"抵扣部分退回额度、实付部分原路退现金"的混合退款规则，需微信支付能力确认 + 财务口径确认。
