# DLS 项目约束文件（最高权威 · 所有 AI 先读）

> 本文件是反幻觉 / 反自说自话的项目级约束。任何 AI（架构师、实现者）进入本仓库，先读本文件，再读 `AGENTS.md`，然后才是 SPEC / TASK。
> 本文件与产品方最新显式决策冲突时，以决策为准，并**回写本文件**。

---

## 1. 事实权威链（从高到低）

1. 产品方最新显式决策（`docs/decisions/DECISION-LOG.md`）
2. `30-approved` SPEC
3. 本文件第 3 节「已锁定事实」
4. 现有代码 / 测试 / 运行时证据
5. 领域文档（`手册 v3`、`CONTEXT.md`、`知识库\02_知识卡片\`）
6. 模型知识 / 行业惯例 / 聊天上下文 —— **永远不是事实来源**

无来源可引的断言 = 幻觉嫌疑，禁止用于决策。

## 4. 证据标签纪律

影响决策的每条陈述必须带标签 + 来源：

- `[VERIFIED]`：在具名文件/命令输出/运行时/被引外部源中观察到
- `[INFERENCE]`：从已核实事实推理，但未直接观察
- `[PROPOSAL]`：建议，未批准
- `[UNKNOWN]`：缺失信息，禁止编造

---

## 5. 幻觉禁区（本项目高发）

1. **不编造测试/迁移/部署结果**：说"通过"必须是真跑过，附命令与输出。
2. **不编造 API / 依赖 / 文件 / 表结构**：先 `search` / `inspect` 再声称存在。
3. **不编造业务规则**：价格、返利、承诺量、保护期、考核阈值——一律引用第 2 节或 SPEC。
4. **不把"常见做法 / 我建议 / 行业惯例"当事实**。
5. **不把讨论当批准、想法当需求、描述当授权**。

---

## 6. 自说自话禁令

1. 结论必须引用来源（文件路径 / 命令输出 / DEC 编号）；无来源断言 = 幻觉嫌疑，作废。
2. 禁止"先假设、后当成事实"的自我循环：假设一旦被采信，必须回写为决策或显式标注 PROPOSAL。
3. 文档里标了"待确认 / 待裁定"的，不得当作已定。
4. 不填充未确认的目录、材料、时间线、阶段、合作方式、审批状态。
