# SPEC-0002 · 代理商档案域

- 版本：v0.1.0
- 状态：30-approved（产品方批准 2026-08-13，DEC-0023；仅批准 SPEC，未授权实现）
- 日期：2026-08-13
- 授权：无（本 SPEC 批准前不写代码）

## 背景与目标

SPEC-0001 交付了规则配置域（档位/价盘/返利等配置）与纯函数引擎。本 SPEC 建立**代理商档案域**：合作方、代理商档案、协议、区域占用、保证金五类聚合 + **试销期生命周期状态机**，并补齐 AC-004 的 DB 唯一索引（region 占用表）。

依据：DEC-0021（跨域缺口移交）、项目约束事实 1/9/12、手册 v3 第十五~十八条/第二十五条。

## 术语

| 词 | 定义 |
|---|---|
| 合作方 | 自然人或法人，可持多重身份（代理/经销/合伙），分别签协议记账 |
| 代理商档案 | 代理商在系统中的核心记录：档位、区域、年度承诺、生命周期状态 |
| 试销期 | 新签代理 3 个月考察期；转正 = 完成首批进货 + 启动终端销售 |
| 区域保护 | 转正后激活的排他权，非签约即享 |

## 范围

- 包含：5 张表 ORM + 迁移（`party` / `agent_profile` / `agreement` / `region_occupancy` / `deposit`）、试销期状态机（纯函数）、区域占用互斥（DB 唯一索引 + 应用层）、档案创建/查询命令。
- 不包含：订单/回款/返利结算/抵扣流水（订单账务域，SPEC-0003）、管理后台 UI（SPEC-0004）、微信登录/支付、裂变/引荐（DEC-0006 暂缓）。

## 需求（R-xxx）

- **R-001** `party`：名称、统一社会信用代码/身份证、资质、微信 openid/手机号（绑定）。
- **R-002** `agent_profile`：party_id、档位（区县/地级市）、区域（city_code/district_code）、年度承诺、季度分解值、生命周期状态。
- **R-003** `agreement`：区域/档位/年度承诺/保证金条款/首批货款/有效期/签署状态。
- **R-004** `region_occupancy`：区域占用表，`(city_code, district_code)` 唯一索引——补 AC-004 的 DB 约束；同地级市 地级市/区县互斥（复用 TASK-0003 `region_guard` 应用层校验）。
- **R-005** `deposit`：类型（保证金/首批货款）、金额、减免/延期、退还。
- **R-006** 试销期状态机：意向 → 资质审核中 → 待签约 → 试销期 → 转正（区域保护激活）/ 试销失败（协议解除）。转正条件 = 试销期届满 **且** 完成首批进货 **且** 启动终端销售。
- **R-007** 档位/承诺量/保证金/首批货款**从 `agent_tier` 配置读取**（规则即数据，不硬编码）。
- **R-008** 区域保护 = 转正后激活（状态与区域占用绑定：只有转正才占区域）。
- **R-009** 代理商档位/区域颗粒度仅 **区县级 + 市级**（DEC-0022，省级/大区不考虑，S/A/B/C 区域分级不采用）；`agent_tier.max_region_grade` 字段作废，迁移 0002 删除。

## 验收标准（AC-xxx）

- **AC-001** 5 张表迁移可离线生成（`alembic upgrade head --sql`），schema 测试全绿。
- **AC-002** 状态机金样本：试销届满+首批✓+销售✓ → 转正；首批✗ → 解除；销售✗ → 解除；未届满 → 不变；非法迁移 → 报错。
- **AC-003** `region_occupancy` 唯一索引存在（DB 层），且应用层 `region_guard` 互斥通过金样本。
- **AC-004** 档位数据读自 `agent_tier` 配置（写测试证明非硬编码）。

## 技术要点（DEC-0011 已锁定）

- ORM/Alembic 沿用 TASK-0004 模式（`RuleConfigMixin` 版本化字段不适用于本域——本域是业务聚合，非版本化配置；仅 `region_occupancy` 需唯一约束）。
- 状态机为**无副作用纯函数**，接受外部信号（首批进货完成 / 启动终端销售 / 试销期届满）——信号来源（订单域）在 SPEC-0003 提供，本域不实现订单逻辑。
