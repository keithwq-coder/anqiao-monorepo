# 中科安樵 CRM

内部 B2B/G CRM 的领域词汇表。用于统一"客户、角色、商机、公池"等核心术语，
避免"客户/机构/代理"混用导致权限与归属模型歧义。只记录本项目的领域概念，
不含实现细节（表名、框架、代码路径另见 ARCHITECTURE.md 与各 SPEC）。

## 角色

**管理员（administrator）**：
唯一能全局看完整详情、无理由修改任何业务记录（自动留痕）、管理账号/角色/
停用/点名分配/进池/归档的内部身份。
_Avoid_: 超级管理员、root

**其他管理层（manager）**：
仅可查看明确授权范围内的脱敏汇总；只读。必须带 scope（范围）。
_Avoid_: 主管（主管若需全公司范围应授 administrator）

**业务人员（business_user）**：
销售。名下客户完整可见可写，他人客户脱敏可见 + 销售进度；可认领公池客户。
_Avoid_: 销售员、员工

（v0.4.1 / `DEC-0172`：原「总经理（general_manager）」角色已删除，其点名分配/
进池能力归并至 administrator；全公司脱敏摘要由 administrator 查看。）

**未授权主体**：未登录、停用、无角色者。不能读任何业务内容。

## 客户与类型

**客户**：
CRM 中的一条业务记录，代表一个交易/合作对象。所有客户共用一套归属、脱敏、
公池、商机规则。
_Avoid_: 机构、企业、对象（这些是旧的/过窄的叫法）

**客户类型**：
每个客户必填的一个分类值，纯标签，不改变行为。三个值：直接采购 / 个人 / 渠道。
_Avoid_: 客户等级、客户细分（类型不是等级）

**直接采购**：
通过集采、招投标、做项目等方式直接采购的客户。
_Avoid_: 机构客户、B 端客户

**个人**：
通过团购、电商、一件代发、带货等个人渠道购买的客户。第一版仅预留该类型值，
不落地个人建档/跟进/商机流程，不接个人隐私（PII）。
_Avoid_: C 端客户、消费者

**渠道**：
代理、经销商等中间渠道。纯标签，不做渠道层级与佣金结算。
_Avoid_: 代理商、经销商（作为类型，二者是"渠道"的子例，不单独建类型）

## 归属

**负责人（owner）**：
一条客户当前的责任归属。是记录关系，不是永久角色；同一人可负责多条客户。
_Avoid_: 归属人、负责人角色

**公池**：
客户"暂无负责人"的状态集合。进池的客户 owner 为空，对全体业务角色脱敏可见，
等待认领。进池与认领都留审计与历史。
_Avoid_: 公海、未分配池（统一叫公池）

**认领（claim）**：
业务人员把一条公池客户转为本人负责的动作。认领即成为负责人，获得完整详情。
_Avoid_: 领取、抢占

**点名分配（transfer/assign）**：
admin 把客户直接转交给某个具体人。理由可选（自动留痕）。
_Avoid_: 转交（转交是旧称，统一用"分配"；但与"进池"是两种不同去向）

**进池（release to pool）**：
admin 手动把客户从某负责人名下转为无主状态。写负责人历史 + 必填原因。

## 商机与跟进

**商机（opportunity）**：
AI 参与判断"有没有新的商业机会"的候选，附理由，由**人最终裁定**采纳或忽略。
不是"漏跟进提醒"，与跟进是两层。
_Avoid_: 提醒、线索（线索是外部爬取的候选，见下）

**商机来源**：
① 基于现有客户（客户档案 + 爬虫匹配到老客户）；② 网络爬虫（外部公开信息，
如招投标/集采公告）。AI 给候选 + 理由，人裁定后：老客户命中通知其负责人，
新主体进公池待认领。
_Avoid_: 把"基于现有客户"理解成"基于跟进记录"——这是错的

**跟进（follow-up）**：
销售对某客户的一次活动记录（事实正文、下一步、待办）。与商机分层，商机采纳后
才通过跟进流程落地行动。
_Avoid_: 商机（商机≠跟进）

**督促（urge/overdue list）**：
admin 的只读逾期清单（谁、哪条客户、待办内容、逾期多久）。只读，不触发动作。
_Avoid_: 提醒、催办（系统不代为催办）
