## 1. Problem

当前系统只有只读管理摘要（`management_summary`），没有任何结构化报表与数据
导出能力。股东（赵、武）与 CEO（吴）需要按归属人/管理人、客户类型、地区、
来源等维度统计业务并导出 Excel 核对业绩，当前无法做到。SPEC-0008 明确
「search only, no export」；SPEC-0010（报表/漏斗/预测）曾 dropped——但产品
负责人 2026-08-26 明确要求报表能力（不含漏斗/预测，因系统无销售阶段与评分）。

## 3. Goal and success measure

提供面向管理层（administrator；shareholder+business_user 的赵/武）的报表
页面与 Excel 导出：客户统计、销售业绩（按归属人/管理人，**含金额汇总**）、
跟进活动、公池动态四类；每个报表遵守权限与脱敏规则，导出文件只含当前用户
有权查看的数据。非技术验收：吴/赵/武登录后进入「报表」页，选择时间范围与
口径，看到对应统计并可一键导出 Excel，打开文件数字与页面一致；业绩报表能
看到每人名下客户的金额合计。

## 4. Non-goals

- 不做销售漏斗、预测、评分、**商机金额**统计（系统无商机金额字段；客户金额
  汇总由 R-002 承担，不引申为商机/成交额）。
- 不做拖拽式 BI 自助建模/自定义图表（第一版为固定报表 + 固定维度筛选；自定义
  报表编辑器属于后续迭代，非本版本）。
- 不做目标值录入与达成率（无目标管理模块；本版本只统计既有数据）。
- 不做实时推送/订阅（报表为按需生成）。
- 导出不包含敏感字段原文（遵守 SPEC-0001 脱敏）。业绩口径按 `owner_user_id`
  还是 `custodian_user_id` 见 SPEC-0002 v0.5.0 OD-006（默认业绩=归属人，
  管理人维度另行聚合）。

## 5. Users and permissions

| 角色 | 报表可见性 |
|---|---|
| administrator（吴） | 全部四类报表，全公司数据（脱敏聚合） |
| shareholder + business_user（赵/武，SPEC-0002 v0.5.0） | 全部四类报表，全公司数据（脱敏聚合） |
| manager | 保留现状（管理摘要只读）；报表页入口是否向其开放由 OD 定（默认不开放） |
| business_user | 不开放报表页（默认）；个人维度统计后续按需 |

> 第一版报表入口仅对 administrator 与 shareholder+business_user（赵/武）开放。
> 报表数据为**聚合统计**而非明细清单；明细字段遵循 SPEC-0001 脱敏投影。

## 6. Required behavior

### 报表列表（R-001…R-004）

- R-001: **客户统计报表**——维度：客户类型（直接采购/个人/渠道）、地区、
  来源分类；指标：客户数、公池数、新增数（按时间范围）；支持按
  `time_range`（如近 7/30/90 天、自定义起止）与维度筛选。
- R-002: **销售业绩报表**——按「归属人」（`owner_user_id`）或「管理人」
  （`custodian_user_id`，SPEC-0002 v0.5.0 新增）两个口径之一聚合；指标：客户
  数、新增客户数、当前有效跟进数、**金额合计**（客户金额字段，SPEC-0001
  扩展）；可按人员排名（榜单），时间范围筛选。
- R-003: **跟进活动报表**——按跟进方式类别（电话/微信/面谈/其他）、跟进人员、
  月份统计跟进次数；提供"近月有跟进客户数/无跟进客户数"概览。
- R-004: **公池动态报表**——公池客户总数、按地区/类型分布、认领/释放/进池
  记录数（时间范围筛选）。

### 权限与脱敏

- R-005: 所有报表聚合只使用当前用户经 `project_record` 有权查看的记录计算；
  任何一处无权数据不得进入统计（R-013/R-023 硬边界）。
- R-006: 报表不展示联系方式的明细值（电话/微信/邮箱），只展示计数与聚合；
  导出文件同样遵守。
- R-007: 管理摘要（management_summary）逻辑可被报表复用，但报表必须按 R-005
  重新校验权限，不得假设摘要结果可直接用于导出。

### 导出

- R-008: 每个报表提供「导出 Excel」按钮；导出文件为 `.xlsx`（UTF-8），内容与
  页面当前筛选条件下的统计一致；文件名含报表名与日期。
- R-009: 导出走与页面同一权限与服务端逻辑（不允许前端拼接数据再导出绕过
  权限）；导出动作写审计（actor/报表/筛选条件/时间，不记录明细值）。
- R-010: 数据量为聚合行（行数 = 维度组合数），不超过系统分页量级；大范围
  筛选导出需有行数上限保护（如超上限提示缩小范围或分页导出，工程决策确定）。

### 页面与入口

- R-011: 导航新增「报表」入口，仅对有报表权限的用户可见（administrator 与
  shareholder+business_user 赵/武）；页面含四类报表的 Tab 或分区、筛选控件、
  导出按钮。
- R-012: 空结果与无权场景明确区分提示；报表加载失败显示可重试错误而非空表。
- R-013: 「金额合计」仅统计客户金额字段（SPEC-0001 扩展，可选）为有效数值的
  记录；金额为空/未填写的记录计入客户数但不计入金额合计，报表页注明口径。

## 7. Acceptance criteria

- AC-001: administrator（吴）与 shareholder+business_user（赵/武）登录后可见
  「报表」入口，business_user 不可见（默认）。
- AC-002: 四类报表各能按时间范围/维度筛选出正确统计数；抽查计数与
  `/api/admin/summary` 及客户列表总数一致（同一数据集）。
- AC-003: 销售业绩报表按归属人口径与按管理人口径各拉一次，客户 X（归属=赵、
  管理人=何，SPEC-0002 v0.5.0 AC-029）分别出现在赵的归属报表与何的管理报表。
- AC-004: 导出 Excel 成功打开，行数与页面统计一致；文件中不含电话/微信/邮箱
  等联系方式明细（如有维度列，仅类别）。
- AC-005: 非 administrator / 非 shareholder 直接访问报表端点（无 UI 入口
  绕过）→ 403，不泄露数据。
- AC-006: 业绩报表金额合计 = 口径内客户金额字段之和（可抽查 2-3 名销售核对）。
- AC-007: 全量 `pytest tests -q` 不回退（基线 504 passed, 28 skipped）。

## 8. Risks / open questions

- OD-007: 报表是否向 manager（赵/武以外的管理岗，如未来新增）开放？默认不开放
  （仅 administrator 与 shareholder+business_user），避免与 manager scope
  摘要语义混淆。
- OD-008（已决策，2026-08-26）: 业绩报表**需要金额汇总**——客户表新增可选
  金额字段（SPEC-0001 扩展），报表按归属人/管理人汇总金额合计。金额语义
  （合同金额/年采购额/累计成交额）由 SPEC-0001 扩展时与产品负责人确认。
- OD-009: Excel 导出依赖新依赖（如 openpyxl/pandas）——工程决策，实现任务内
  确定并纳入依赖治理。
- OD-010: 客户金额字段的**录入/编辑权限**与显示规则（谁可填、是否脱敏展示、
  报表是否显示明细金额）——随 SPEC-0001 金额扩展共同确定。
- **OD-010 已解决（2026-08-27）**：金额字段已作为 `amount NUMERIC(15,2)` 列
  添加到 `institutions` 表（迁移 0016），创建/编辑客户时可选填写，报表按
  归属人/管理人汇总金额合计。
- 本草案为 DRAFT：不授权实现。需 review → 30-approved（approval.json hash
  匹配）→ 活动任务卡 → 单独实现授权（AGENTS.md §5）。
