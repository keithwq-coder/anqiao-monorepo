- ✅ 减少人工提醒工作（逾期跟进自动通知）

```markdown

触发类型：当记录被创建时
筛选条件：全部新记录
```

## ⚠️ 规则 2：逾期跟进提醒

### 触发配置
```markdown
触发源：定时任务
时间设置：每天 09:00（工作日）
筛选条件：
  - 「下次跟进时间」= TODAY()
  - AND「跟进状态」≠ "已成交"
  - AND「跟进状态」≠ "已流失"
```

### 执行逻辑（飞书多步操作）

#### Step 1：查询符合条件的客户
```python
# 伪代码示例
query = {
    "filter": {
        "condition": "AND",
        "rules": [
            {"field": "下次跟进时间", "operator": "=", "value": "TODAY()"},
            {"field": "跟进状态", "operator": "NOT_IN", "values": ["已成交", "已流失"]}
        ]
    }
}
customers = fetch_customers(query)
```

#### Step 2：组装消息内容
```json
{
  "message": "⚠️ 今日待跟进客户提醒\n\n您有 {{计数}} 个客户今天需要联系：\n\n",
  "customer_list": []
}
```

#### Step 3：逐条生成提醒卡片
```json
{
  "tag": "notice",
  "level": "warning",
  "content": "【{{序号}}】{{客户名称}}（{{联系人}}）\n电话：{{联系电话}}\n上次跟进：{{最后跟进日期}}\n当前状态：{{跟进状态}}\n商机关联：{{商机关联金额}}万元"
}
```

#### Step 4：发送消息并@负责人
```json
{
  "at_users": ["{{负责人 ID}}"],
  "message": "⚠️ 今日待跟进客户提醒\n您有 {{计数}} 个客户今天需要联系...\n\n[点击直达客户详情页]",
  "deep_link": "https://www.feishu.cn/baas/{{table_id}}/page/{{page_id}}"
}
```

### 完整流程图

```
定时触发 (09:00)
    ↓
扫描今日需跟进客户
    ↓
过滤掉已成交/已流失
    ↓
按负责人分组
    ↓
批量生成提醒消息
    ↓
@对应人员发送
    ↓
记录发送日志（避免重复）
```

### 高级功能配置

#### 分级提醒策略
```markdown
如果「客户等级」= A 级：
  → 发送强提醒（弹窗 + 声音）
  → 同时抄送直属上级
  
如果「客户等级」= B 级：
  → 普通提醒（仅应用内通知）
  
如果「客户等级」= C 级：
  → 延迟提醒（下午 15:00 二次推送）
```

### 注意事项
⚠️ 确保每个客户都有明确的「负责人」字段  
⚠️ 检查「下次跟进时间」是否填写  
⚠️ 设置重试机制（失败后 30 分钟再试一次）

## 💰 规则 3：大额商机预警

### 触发配置
```markdown
触发源：客户信息表
触发类型：当字段值变化时
监控字段：商机关联金额
触发条件：商关联金额 > 50（万元）
```

### 执行动作

#### 方式 1：直接通知（简单版）
```json
{
  "message_type": "alert",
  "title": "💰 大额商机预警",
  "content": "【重要】发现大额商机！\n\n客户：{{客户名称}}\n金额：{{商关联金额}}万元\n预计成交时间：{{预计成交时间}}\n负责人：{{负责人}}\n\n请及时汇报进展！",
  "recipients": [
    "{{负责人}}",
    "{{部门负责人}}"
  ]
}
```

#### 方式 2：审批流程（严格版）
```markdown
Step 1: 发送预警通知给负责人
Step 2: 等待负责人提交详细报告
Step 3: 自动转发给部门主管审核
Step 4: 审核通过后存入「大额商机库」
```

### 分层预警配置

根据金额大小分级处理：

| 金额范围 | 预警级别 | 通知对象 | 行动要求 |
|---------|---------|---------|---------|
| 50-100 万 | 黄色预警 | 负责人 + 主管 | 每日汇报进展 |
| 100-200 万 | 橙色预警 | 总监级别 | 每周专题汇报 |
| 200 万以上 | 红色预警 | 高管团队 | 成立专项小组 |

### 触发配置
```markdown
触发源：定时任务（智能分析）

  - 「跟进状态」IN ("未接触", "初次接触", "方案演示", "报价中", "谈判中")
  - AND「下次跟进时间」+ 7 天 < TODAY()
  - AND「最后跟进时间」+ 7 天 < TODAY()
```

#### Step 1：识别潜在流失客户
```python
high_risk_customers = []
for customer in all_active_leads:
    days_since_followup = today() - customer.last_followup_date
    if days_since_followup >= 7 and customer.status != "已成交":
        high_risk_customers.append(customer)
```

## 🛠️ 自动化规则最佳实践

### ✅ 推荐做法

1. **先测试后上线**
   - 所有规则先在测试环境验证
   - 使用模拟数据跑通整个流程
   - 确认不会误触其他业务

2. **设置缓冲期**
   ```
   第 1 周：观察模式（只记录不执行）
   第 2 周：部分执行（仅 A 级客户生效）
   第 3 周：全量启用
   ```

3. **建立监控机制**
   ```json
   {
     "log_rules": [
       "每次触发的时间、条件、结果",
       "发送成功的消息数量",
       "失败的消息及原因"
     ],
     "alert_threshold": 错误率 > 10%
   }
   ```

4. **定期审查优化**
   ```
   每月：
   - 查看各规则的触发频率
   - 收集用户反馈（有用/无用）
   - 关闭或修改低价值规则
   ```

### ❌ 避免的错误

1. **过度自动化**
   ❌ 一条记录触发 5 个以上的动作  
   ❌ 短时间内密集推送多条消息  
   ✅ 保持简洁，聚焦核心场景  

2. **缺乏容错**
   ❌ 没有异常处理逻辑  
   ❌ 网络中断后无法恢复  
   ✅ 添加重试机制 + 降级方案  

3. **忽略性能**
   ❌ 一次性查询 1000+ 条记录  
   ❌ 在高峰时段执行复杂计算  
   ✅ 分批处理 + 错峰执行

## 💡 常见问题 FAQ

**Q1：规则配置在哪里？**
A：飞书多维表格 → 点击「 automations」按钮 → 选择「新建自动化规则」

**Q2：如何测试规则是否生效？**
A：手动创建一条测试客户 → 观察是否在 1 分钟内收到通知

**Q3：能设置多个规则吗？**
A：可以无限叠加，但建议不超过 10 条，避免混乱

**Q4：规则执行失败怎么办？**
A：查看「自动化日志」→ 找到失败记录 → 根据错误提示修复

**Q5：能不能设置规则优先级？**
A：目前没有直接设置，但可以通过「触发条件」的复杂度间接控制
