# ADR-0004: 权限模型、客户类型、公池与商机重定义

- Date: 2026-08-13
- Status: PROPOSED
- Decided by: Product owner（grilling 会话逐题确认）；本 ADR 记录领域模型形状，
  产品行为授权以 `DEC-0149` 为准
- Affects: 领域模型与后续 SPEC 修订（SPEC-0001 / SPEC-0002 / SPEC-0003）
- Supersedes: 无（首个领域模型 ADR）

## Decision scope

本 ADR 记录一次领域建模会话的结论：四角色权限模型、客户三类型、公池归属机制、
以及"商机 = AI 判断新商业机会（人裁定）"的定义。它是术语与模型形状的单一事实
来源（对应 `CONTEXT.md`），不授权任何代码、迁移、部署或生产变更。

## 模型形状

1. **四个登录角色**（`agent` 登录角色废弃）：
   - `administrator`：全局完整可看 + 无理由改业务记录（自动留痕）+ 账号/角色/
     停用 + 点名分配 + 进池 + 归档。
   - `general_manager`：全局脱敏只读 + 脱敏商机 + 逾期督促清单（只读）+ 点名
     分配（必填理由）+ 进池。不直接改客户内容。
   - `business_user`：名下完整 / 他人脱敏+进度 + 认领公池客户。
   - `manager`：范围只读（保留，需 scope）。
   - `agent`：作为**登录角色**废弃；"代理"回归为**客户类型**（渠道的一个子例）。

2. **客户 = 一张记录**，加一个"客户类型"字段，三值纯标签：`直接采购` / `个人` /
   `渠道`。类型不改变任何行为，只用于分类/筛选/统计。`个人` 第一版仅预留值，
   不落地流程与 PII；`渠道` 不做层级与佣金结算（non-goal）。

3. **公池 = 无主状态**：owner 可空 + 显式"在池"状态。进池是 admin/gm 手动动作，
   写负责人历史 + 必填原因；池中客户对全体业务角色脱敏可见；business_user 可
   认领（认领即成为负责人，留审计），第一版不设防囤积护栏。

4. **商机 = AI 判断新商业机会（候选 + 理由，人最终裁定）**：两个来源——现有客户
   （档案 + 爬虫匹配老客户）与网络爬虫（外部公开信息，如招投标公告）。AI 不直接
   判定、不自动建档。人采纳后：老客户命中通知负责人，新主体进公池待认领。这与
   旧 SPEC-0003"AI 只写理由、本地规则裁决"不同，是范围重定义。

## 关键边界（防回退）

- "商机"绝不等同于"跟进/漏跟进提醒"，二者分层。
- AI 无最终判定权；采纳权在人。AI 不能把外部主体直接建为客户。
- admin 的"无理由改"仍须自动留痕（谁、何时、改了哪条），不取消审计底线。
- 公池客户 owner 为空，脱敏投影（`owner_user_id == user.id`）对无主客户必须单独
  定义可见性，不得因"无主"而拒绝所有人或对所有人放开。

## Consequences

- 后续 SPEC 修订草案据此落地：SPEC-0001 加客户类型+公池、SPEC-0002 废 agent 角色、
  SPEC-0003 重定义商机。
- 产品行为授权记录于 `DEC-0149`；本 ADR 只描述模型，不授权实现。
- 生产上已存在的 zxx 登录账号与迁移 0007 是旧模型产物，其纠正需单独生产授权，
  不在本 ADR 范围内。
