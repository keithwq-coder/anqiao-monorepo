## 📜 项目宪法：Karpathy Vibe Coding 原则（必须遵守）

### 核心精神

```
1. 保持简单愚蠢 (KISS)
   - 优先选择最简单可行的方案
   - 不过度设计，不追求完美
   - 能用现成工具就不自己写
   - "Make it work, make it right, make it fast" 的顺序不可颠倒

2. 快速迭代胜过精雕细琢
   - 先做出 MVP（最小可用产品）
   - 通过反馈循环快速改进
   - 每个版本都要可运行、可测试
   - 不要花超过 30% 的时间在理论上

3. 拥抱实用主义
   - 技术选型以解决问题为导向，而非追新
   - 接受不完美的解决方案，只要它能工作
   - 代码的可读性 > 代码的精巧性
   - 如果重构不能带来明显的收益，就别重构

4. 以人为本
   - 让工具和流程服务于人，而不是反过来
   - 自动化应该减少疲劳工作，不是增加复杂性
   - 用户友好 > 技术优雅
   - 文档要实用，不需要面面俱到

5. 实验驱动开发
   - 不确定就做实验验证假设
   - 小步快跑，快速失败
   - 用数据说话，不用直觉
   - 保持好奇心，持续学习新技术但别盲目跟风
```

### 执行准则

当你面对技术选择或设计方案时，必须问自己：
- ❌ 这是在追求技术完美还是解决问题？
- ❌ 这个复杂度真的必要吗？
- ❌ 有没有更简单的替代方案？
- ❌ 能不能今天先跑起来再说？
- ❌ 一年后回头看会后悔这个决定吗？

**答案倾向于"是"的话 → 重新简化！**

## 🏗️ 项目上下文

### 1️⃣ 系统定位

**一个后台智能分析引擎，用于主动发现商机并赋能销售团队。**

核心能力：
- 📊 **深度数据分析**：综合分析多渠道信息，挖掘业务洞察
- 🔍 **主动商机挖掘**：从碎片化信息中发现商业机会
- 🤝 **客户维护建议**：判断何时联系、如何联系最合适
- 💬 **沟通赋能**：模拟对话场景，提供应对策略

**非执行型 AI**：不做机械执行动作，而是像销售主管一样思考和指导

### 2️⃣ 技术架构（三层）

```
┌──────────────────────────────────────┐
│  表现层：飞书 App/Web                 │
│  (成熟稳定，无需开发，零成本集成)      │
└──────────────┬───────────────────────┘
               │ Webhook/API
┌──────────────▼───────────────────────┐
│  业务层：Python FastAPI/Flask 代理    │
│  (- AI 调度器、爬虫协调器、通知推送)     │
└──────────────┬───────────────────────┘
               │
┌──────────────▼───────────────────────┐
│  数据层：飞书 Base API + AI 中转站    │
│  (- 数据存储、AI 调用、互联网扫描)       │
└──────────────────────────────────────┘
```

### 3️⃣ 技术栈

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| 前端 | 飞书原生 | 零开发成本，体验好 |
| 后端 | Python + FastAPI | 已有基础，生态丰富 |
| 爬虫 | Playwright (headless) | 你已有项目经验 |
| AI | 你的第三方中转站 | 无额度限制，模型可选 |
| 部署 | Docker Compose | 标准化、易维护 |
| 测试 | pytest + httpx | Python 标准工具 |

### 4️⃣ 关键约束

1. **数据隐私**：客户信息不得泄露给未授权方
2. **权限隔离**：每个人只能看到自己负责的客户
3. **响应时间**：AI 分析必须在 30 秒内返回结果
4. **可靠性**：AI 扫描服务 99% uptime
5. **成本控制**：AI 调用费用控制在¥3000/月以内

### 当你在写代码时...

```python
# ✅ 好的注释方式
class SalesOpportunityAnalyzer:
    """
    智能商机分析器
    
    核心逻辑：
    1. 从多维表格获取待扫描客户列表
    2. 并行调用多个数据源（工商/新闻/招聘等）
    3. AI 综合分析这些信息，生成洞察报告
    4. 如果检测到高价值信号，触发推送通知
    
    性能优化：
    - 使用 aiohttp 并发请求，减少 IO 等待
    - 对搜索结果做缓存，避免重复扫描
    - 批量处理请求，控制 AI Token 消耗
    """
    
    def analyze_customer_opportunities(self, customers):
        # 分批处理，每批 10 个客户，避免内存溢出
        batch_size = 10
        
        for i in range(0, len(customers), batch_size):
            batch = customers[i:i+batch_size]
            
            # 跳过已扫描过的客户（通过 last_scan_time 标记）
            fresh_customers = [c for c in batch if not self.is_fresh(c)]
            
            if not fresh_customers:
                continue
            
            results = await self._analyze_batch(fresh_customers)
            await self._notify_high_priority(results)
```
