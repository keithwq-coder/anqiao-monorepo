# UX 改进任务编排（wiki 培训系统）

> 角色分工：**本文件只做任务编排与验收口径**；具体实现由 reasonix 执行，执行结果回交本文件作者做"任务成果审查"。
> 来源：UX 审查报告（经销商 / 内部销售 / 管理人员三类视角）+ 既有 `docs/improvements.md`（I-1~I-6）。本编排补充了原文档未从角色视角点出的缺口：**T1 测验纠错闭环、T2 内部销售管商视图、T8 渠道差异化、T9 学习凭证、T10 移动端**。
> 原则：surgical 改动；每项带可验证验收；标注范围文件与依赖；认证口径 B 不变（见 `SPEC.md §6`）。
> 状态图例：`ready`=可立即排期；`blocked`=需业主先拍板（见文末 B-Q）。

## P0

### T1 · 测验错题回显（经销商 · 学习闭环）
- **状态**：ready
- **目标**：考不过能看到「哪题错、我选了啥、正确答案是啥」，形成 测→纠→再测 闭环。
- **范围文件**：
  - `src/app/pages` 不改；改 `src/app/api/quiz/[moduleId]/submit/route.ts`：判分后随结果回显每题 `{ordinal, question, chosen, correct}`（仅 POST submit 返回）。
  - `src/app/m/[id]/quiz/page.tsx`：未通过卡片按题展示错题明细。
- **不动的安全边界**：GET `/api/quiz/[moduleId]` 取题**仍不含 `answer`**；答案只在服务端判分后随本次结果回显一次，不进取题接口、不入日志。
- **验收**：① 重考页逐题显示错题题干+我的选项+正确选项；② `curl` 取题接口 JSON 无 `answer` 字段；③ 认证口径 B 不受影响。
- **依赖**：无。

### T2 · 内部销售「名下经销商进度」视图（内部销售 · 管商）
- **状态**：blocked → B-Q1
- **目标**：内部销售登录后可见所管渠道的聚合进度（认证率、未完成 TopN），而非纯学员视角。
- **范围文件**（待定）：新增只读汇总页/区块；复用 `src/lib/certification.ts` 的认证计算 + `src/lib/admin.ts` 列表能力；内部销售**不可见** `/admin` 后台。
- **阻塞**：系统当前**无「经销商→销售」归属关系字段**，须业主先定义归属规则（按区域？按建号？全部？）。见 B-Q1。
- **验收**（草案）：内部销售可见聚合进度（认证率、未完成 TopN），无单账号敏感信息越权；非 admin 角色不能访问 `/admin`。
- **依赖**：B-Q1。

### T3 · 占位账号治理 + 文档口径统一（管理 · 数据治理）
- **状态**：ready（执行前先确认 B-Q2）
- **目标**：后台列表/统计/导出默认不含 99 个 `dl_0001~dl_0099` 占位；SPEC/README/seed 三处账号数表述一致。
- **事实核查**：种子 `seed/auth.json` 实测含 **114 用户（admin 11 / internal_sales 2 / internal_tech 1 / internal_ops 1 / dealer 99）**；与 `SPEC.md §8「不导入 99 占位」`直接矛盾；`README.md` 又说「导入 113」。
- **范围文件**：
  - `scripts/seed.mjs`：确认是否真导入 99 占位；若保留则加 `is_placeholder` 标记（新增列或在 `users` 表加 `is_placeholder boolean`）。
  - `src/lib/admin.ts`（`listUsersWithCert`）、`src/components/AdminPanel.tsx`、导出接口：默认隐藏占位。
  - `SPEC.md` / `README.md`：统一账号口径表述。
- **验收**：① 后台默认不显占位；② 统计「已认证数」不含占位；③ SPEC/README 账号口径一致无矛盾。
- **依赖**：B-Q2（是否导入占位）。

## P1

### T4 · 「已学」判定加强（经销商 · 认证严肃性）
- **状态**：ready（对应 `docs/improvements.md` I-4）
- **目标**：区分「已浏览 / 已学完」，避免「打开即完成」弱信号误标学完。
- **范围文件**：
  - 迁移：在 `course_views` 增 `has_completed boolean`。
  - `src/app/m/[id]/page.tsx`：课件页滚动到底发一次信号置 `has_completed=true`。
  - `src/lib/certification.ts`：查询带 `has_completed`；认证口径 B 不变（仍按「出现即 viewed」）。
  - `src/app/page.tsx`：状态文案由「已学习」改为「已浏览 / 已学完」二态。
- **验收**：仅打开不滚到底=已浏览（不计学完语义）；认证仍按出现即 viewed；仪表盘文案区分二态。
- **依赖**：无。

### T5 · 学习路径与顺序引导（经销商 · 引导）
- **状态**：ready
- **目标**：新用户不再面对平铺 16 卡，路径清晰。
- **范围文件**：`src/app/page.tsx`：用 `layer`(L1/L2/L3) + `ordinal` 分组/排序并标注推荐顺序；首屏「从必修开始」空态引导。
- **验收**：仪表盘按层级分组、标注推荐学习顺序；首登有清晰起点引导。
- **依赖**：无。

### T6 · 后台规模化 + 内容质量分析（管理）
- **状态**：ready
- **目标**：百级用户在后台可用；能定位低通过率模块/题。
- **范围文件**：
  - `src/lib/admin.ts`、`src/app/api/admin/users/route.ts`：列表分页 + 排序（完成度、最近活跃）+ 筛选（角色/状态）。
  - `src/components/AdminPanel.tsx`：前端分页/排序/筛选 UI。
  - 新增模块级聚合：各模块通过率、最易错题（基于 `quiz_attempts` 聚合）。
- **验收**：百级用户列表可用（分页/排序生效）；能下钻到「某模块通过率/易错题」内容质量视图。
- **依赖**：无（模块级分析可在现有 `quiz_attempts` 上聚合，无需新表）。

### T7 · 趋势与留存（管理）
- **状态**：blocked → B-Q5
- **目标**：运营看趋势而非仅当前快照。
- **范围文件**（待定）：导出/视图增加时间序列（本月新增认证、活跃下降、长期未登录）。
- **阻塞**：当前无时序数据。需业主确认方案：A) 基于现有 `users.created_at` / `last_active_at` 推算；B) 新增周期快照表。见 B-Q5。
- **验收**（草案）：可看到运营趋势对比，非仅单日快照。
- **依赖**：B-Q5。

## P2

### T8 · 代理商/代销商差异化内容（经销商 · 渠道差异）
- **状态**：blocked → B-Q3
- **目标**：代理商/代销商看到渠道专属内容（如分级返点、铺货规则），而非与经销商完全同套。
- **事实核查**：种子矩阵 `seed/auth.json` 中 `dealer` 与 `agent` 必修模块**完全相同（10 个）**，`reseller` 仅少 M08/M09/M11——系统当前把三类渠道当同义词。
- **范围文件**（待定）：差异内容入 `seed/courseware.json` 或 `module_access` 调整；UI 按角色呈现渠道专属区块。
- **阻塞**：需业主提供渠道专属素材。见 B-Q3。
- **验收**（草案）：agent/reseller 在 M07 等政策模块看到渠道专属内容。
- **依赖**：B-Q3。

### T9 · 学习凭证 / 证书（经销商 · 凭证）
- **状态**：blocked → B-Q4（对应 `SPEC.md` B1）
- **目标**：学完可拿到向客户/上级展示的凭证。
- **事实核查**：`M16 内训师认证`、`M14 新人30天落地` 暗示身份进阶，但 7 角色无「内训师」，系统也无证书 PDF（B1 默认不发）。
- **范围文件**（待定）：至少可下载个人「学习档案」摘要；证书 PDF 二期。
- **阻塞**：B1 证书范围未定。见 B-Q4。
- **验收**（草案）：用户能拿到个人完成凭证（摘要至少可导出）。
- **依赖**：B-Q4。

### T10 · 移动端适配（全员）
- **状态**：ready
- **目标**：最该移动化的经销商群在手机/平板可用。
- **范围文件**：`src/app/layout.tsx` 导航可折叠；`src/components/AdminPanel.tsx` 宽表响应式（非仅 `overflowX`）；课件页可读性。
- **验收**：手机视口（≤390px）下导航、后台、课件均可用无横向溢出。
- **依赖**：无。

### T11 · 密码找回兜底 + admin 重置（全员）
- **状态**：ready（对应 `docs/improvements.md` I-2/I-5）
- **目标**：忘密可由 admin 重置，旧会话失效；自助找回二期。
- **范围文件**：
  - 新增 `src/app/api/admin/users/[id]/reset-password/route.ts`：生成新随机密码（展示一次）+ 置 `must_change_password=true` + 清该用户旧会话。
  - `src/components/AdminPanel.tsx`：操作列加「重置密码」；仅 admin。
  - 登录页 `src/app/login/page.tsx`：placeholder 提示「账号或昵称」均可（I-5 轻量项）。
- **验收**：admin 可重置非 admin 账号并拿到一次性新密码；重置后旧会话失效；登录框有账号/昵称提示。
- **依赖**：无。
