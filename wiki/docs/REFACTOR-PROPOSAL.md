# wiki 重构方案 v1（待业主审批）

> 状态：**草案待审**——本文档为重构的唯一依据，业主批准前不动任何代码。
> 起草：2026-09-26 ｜ 起草人：zcode ｜ 依据：业主三项裁定（内容管线/学习体验/技术架构全不行；内外兼顾；先方案后实施）
> 根因认定（业主原话）：wiki 当年"并未规划，更谈不上 spec，纯粹是 AI 自己写的，业主没审查过"。故本方案第一条纪律 = **一切产出经业主审查，规格先行，AI 只实现**。

---

## 一、现状诊断（为什么推倒）

| 维度 | 现状 | 问题 |
|---|---|---|
| 内容管线 | 课件=仓库里 143KB 的 `courseware.json` 巨型 JSON；题库/词条在 MySQL；种子 `seed/*.json` | 改内容=改 JSON+代码发布，内容团队无法自助；无版本、无审核、无预览 |
| 学习体验 | M01-M16 线性模块 + 知识点词条 339 条 + 练习/考试 | 结构是"AI 想到的堆叠"，无教学设计； dealers/员工/家属混在一个入口 |
| 技术架构 | Next.js 16 + 原生 SQL（pg→mysql2 刚移植）+ 巨型 JSON + 一次性 PROMPT/fix 文件散落 | 数据模型从 JSON 倒灌 DB；认证/进度/考试边界含糊；无管理端 |
| 账号体系 | 已接 CRM 统一验证（此部分健康，**保留**） | — |

## 二、目标定位（内外兼顾，一套系统两副面孔）

| 视角 | 服务对象 | 数据口径 | 入口标识 |
|---|---|---|---|
| **对内·真实培训** | 中科安樵员工（销售/售后/技术/管理，CRM 同名账号） | 真实数据：真实设备（自营 7 台+宿迁 3 台遥测）、真实客户资产（脱敏） | 员工入口（无演示标识） |
| **对外·赋能体验** | 经销商/潜在客户（体验账号，由业主发放） | 设备遥测真实 + 业务数据模拟（机构名全虚构、常驻「演示」标识，PRD §2.3.1） | 体验入口（常驻演示徽标） |

培训内容围绕**四大硬件产品线**组织（PRD §2.2 矩阵）：AI 健康守护仪（ASH-01/ANCE-01，现货量产）、跌倒报警器（AFD-01，量产爬坡）、轨迹分析仪（ATA-01，按单排产）、照护采集仪（ACA-01，按单排产）——而非旧版按 AI 自拟的 M01-M16 平铺。

## 三、目标架构（待业主确认选型）

```
┌ 内容生产端（新增，核心解决"内容管线不行"）──────────┐
│ 管理后台 /wiki/admin（仅 admin/指定内容角色可进）      │
│  · 课件编辑：Markdown + 图片上传（存 pgstore/静态目录） │
│  · 题库管理：单题 CRUD、批量导入（Excel 模板）          │
│  · 课程组装：拖拽编排 章节→课时→随堂测                 │
│  · 版本与审核：草稿→业主审核→发布（提交即留痕）          │
├ 数据层（MySQL anqiao_wiki，表结构重建）────────────────┤
│  courses / sections / lessons / knowledge_terms        │
│  quiz_questions / exams / exam_attempts                │
│  users(镜像) / enrollments / progress / audit_log      │
├ 学习端（重构）────────────────────────────────────────┤
│  按产品线的培训路径 + 课时学习 + 练习 + 考试 + 进度      │
│  内部视角：真实客户/设备案例；外部视角：演示数据+标识     │
└ 认证与账号：沿用 CRM 统一验证 + 本地镜像（已上线，保留）─┘
```

**选型建议与理由**：保留 Next.js 16 + mysql2（团队已有两套同栈系统、移植成果复用）；**推倒的是应用结构、数据模型与内容管线，不是技术栈**。备选（更轻的静态方案/无头 CMS）列为附录待比较，默认不采纳。

## 四、数据模型 v1（要点）

- `courses`（产品线/岗位维度课程）、`sections`、`lessons`（Markdown 正文 + 附件引用 + 时长 + 序）
- `knowledge_terms`（词条库，正文 Markdown，替代旧 339 条 JSON 词条）
- `quiz_bank`（题目与课程解耦，支持被多课程引用）、`exams`（组卷规则：按课程抽题）
- `users`（CRM 镜像，口令哨兵）、`enrollments`（谁在学什么）、`progress`（课时完成/得分）
- `audit_log` 沿用；**全部内容表带 `review_status` 与 `reviewed_by`（业主审查留痕）**

## 五、内容管线与审查纪律（本次重构的立身之本）

1. 业主指定内容负责人（1-2 人）→ 管理后台录入/编辑；
2. 任何内容变更 = 草稿 → **业主审查** → 发布；发布前可在预览环境查看；
3. AI 仅在业主明确指定的范围内辅助（如初稿润色），**产出必须经人审**；
4. 旧 `courseware.json` 内容作为素材清洗导入新模型，**旧结构不迁移**。

## 六、学习端设计（内外兼顾）

- **对内**：按"产品线 × 岗位"两条轴组织路径（销售线：卖点/竞品/报价流程；售后线：安装/标定/故障树/质保；技术线：协议/标定/OTA）。学习完成度与 CRM 客户资产视图打通（销售学完什么课，客户资产视图可见认证徽标）。
- **对外**：经销商赋能课程包（同结构，体验账号访问，界面常驻「演示」标识 + 模拟机构数据）。
- 交互基线沿用现版本已验收的做法：随堂练习、正式考试、知识点地图；视觉重做。
