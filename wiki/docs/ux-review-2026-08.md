# UX 审查报告（经销商 / 内部销售 / 管理人员）

> 审查对象：中科安樵 · 经销商赋能培训系统（wiki）
> 审查角色：资深用户体验官
> 审查日期：2026-08-23
> 方法：通读 `SPEC.md` / `README.md` / `VERIFY.md`、页面与组件源码（`src/app`、`src/components`、`src/lib`）、以及种子数据 `seed/auth.json` 实测；所有结论均附证据，不臆测。
> 关联：团队既有改进编排见 `docs/ux-tasks.md`（T1–T11）与 `docs/improvements.md`（I-1–I-6）。本报告区分「已在计划」与「本次新发现」。

## 一、经销商 / 代理商 / 代销商（一线学员，最大群体）

### D1 · 测验失败 = 学习死胡同　🔴 严重　【已在计划 T1】
- **证据**：提交接口仅返回 `wrongOrdinals`（错题题号位置），不返回「我选了什么 / 正确答案」；`src/app/m/[id]/quiz/page.tsx:142` 仅展示「错题位置：第 X、Y 题」。
- **用户影响**：考不过无法复盘，只能盲猜重考，培训闭环断裂。
- **改进**：判分后随本次结果回显每题 `{题干, 我的选项, 正确选项}`（仅 POST submit 返，GET 取题仍不含 answer）。

### D2 · 首屏无学习路径 / 无续学入口　🔴 严重　【已在计划 T5】
- **证据**：仪表盘 `src/app/page.tsx` 为 16 张模块卡片平铺网格；全仓 grep `continue/resume/recommend` 无任何续学逻辑。
- **用户影响**：新经销商（含长辈用户）面对 16 张卡不知从何入手；每次登录都回到全量首页。
- **改进**：按 `layer`(L1/L2/L3) + `ordinal` 分组排序、标注推荐顺序；首登空态引导「从必修开始」；增加「继续学习」入口。

### D3 · 三类渠道被当成同义词　🟠 中　【已在计划 T8】
- **证据**：实测 `seed/auth.json` —— 经销商与代理商必修模块 **100% 相同**（均为 M02–M11），代销商仅少 M08/M09/M11。
- **用户影响**：代理商的分级返点、铺货规则等专属业务内容无处承载，渠道差异化形同虚设。
- **改进**：需业主提供渠道专属素材后，调整 `module_access` / `courseware.json`，按角色呈现专属区块。

### D4 · "已学完"判定脆弱　🟡 轻中　【已在计划 T4 / I-4】
- **证据**：`src/components/CompleteTracker.tsx` 以「距底 <120px」标记学完，且组件挂载即执行一次 `onScroll()`：短课件在长屏上打开即完成，按 End 直达底部即完成，无显式「完成」动作。
- **用户影响**：弱信号，与真实阅读脱节，「学完」水分大。
- **改进**：保留滚动到底标记，但补充显式「标记学完」按钮；或要求停留时长/阅读进度阈值。

### D5 · 移动端体验不足 + 无自助找回　🟠 中　【已在计划 T10 / T11】
- **证据**：`src/app/layout.tsx` 导航仅靠 `flexWrap` 兼容，无响应式断点；后台表靠 `overflowX` 横滚；登录名形如 `dl_0100` + 强口令在手机输入易错；无自助找回密码（仅 admin 重置）；昵称需首登后才有（鸡生蛋）。
- **用户影响**：经销商多在手机/平板使用，首登改密与日常登录摩擦高。
- **改进**：≤390px 视口下导航折叠、课件可读、后台可用无横溢；登录框持续提示「用户名或昵称」；预留自助找回（二期）。

### D6 · 学完无成果 / 无身份感　🟠 中　【已在计划 T9，本次新强调】
- **证据**：M14《新人30天落地》、M16《内训师认证》暗示进阶路径，但用户学完只有一条进度条；`SPEC.md` B1 默认不发证书，且个人无档案导出入口（仅 admin 可导出）。
- **用户影响**：「我学完了，然后呢？」缺乏向客户/上级展示的凭证与身份认可，削弱一线驱动力。
- **改进**：至少提供个人「学习档案」摘要导出；证书 PDF 待 B1 拍板。

## 二、内部销售人员（internal_sales）

### S1 · 管商盲区：完全看不到所管渠道进度　🔴 严重　【已在计划 T2，核心】
- **证据**：内部销售与经销商看到**完全同一套学员视角仪表盘**（`src/app/page.tsx` 的 `ProfileBanner` 对内部组只显示「学习档案」）；唯一聚合视图 `/admin` 在 `src/app/admin/page.tsx:9` 以 `role!=='admin'` 即拒绝。
- **用户影响**：销售管着几十个经销商，却无法掌握「谁学完、谁卡住、谁长期不活跃」——系统零支持，只能口头催。这是内部销售的核心职能缺口。
- **改进**：新增只读聚合视图（认证率、未完成 TopN）；内部销售不可见 `/admin` 后台。阻塞点：系统无「经销商→销售」归属字段，需业主先界定（按区域 / 按建号 / 全部）。

### S2 · 无角色化工作首页　🟡 轻　【本次新发现】
- **证据**：`internal_sales` 本质是「员工 + 带商」，但系统在 `page.tsx` 只当学员处理，无「我的工作 / 我带的商」入口。
- **用户影响**：与纯学员无差异，待办未聚合。
- **改进**：内部销售首页在档案横幅之上叠加「我带的商」待办/聚合区（与 S1 共用归属数据）。

## 三、管理人员（admin）

### M1 · 后台无分页 / 排序、导出不认筛选　🟠 中重　【已在计划 T6】
- **证据**：`src/components/AdminPanel.tsx` 一次拉全量用户做 12 列横滚表；`src/app/api/admin/users/route.ts` 无 `LIMIT/OFFSET`；界面筛了「角色 + 搜索」，但 `src/app/api/admin/export/[fmt]/route.ts` 不读取任何 query 参数，**导出仍是全量 CSV**。
- **用户影响**：百级账号下表格卡顿、且筛选结果无法导出。
- **改进**：列表服务端分页 + 排序（完成度、最近活跃）+ 筛选；导出继承当前筛选条件。

### M2 · 规模化开户 / 运营成本高　🟠 中　【本次新发现】
- **证据**：`src/components/AdminPanel.tsx` 的 `CreateUserForm` 仅支持单个新建、逐个拿一次性口令、线下分发；无批量导入 / 邀请链接 / 自助注册入口。
- **用户影响**：要给 100 个经销商开户，运营人力成本高、易漏发口令。
- **改进**：支持 CSV 批量建号（预校验命名空间）+ 可转发的一次性邀请链接（口令不下发明文）。

### M3 · 只有快照、无趋势　🟠 中　【已在计划 T7】
- **证据**：后台仅显示当前完成率；无「本月新增认证 / 活跃下滑 / 长期未登录」等时序视图（当前无时序数据）。
- **用户影响**：无法做运营干预（如唤醒沉睡经销商）。
- **改进**：基于 `users.created_at` / `last_active_at` 推算趋势（方案 A），或新增周期快照表（方案 B），需业主选定。

### M4 · 无操作审计　🟠 中　【本次新发现】
- **证据**：建号、改密、`reset-password` 均无留痕；`ux-tasks.md` 亦提及「无操作审计」未单列任务。
- **用户影响**：100+ 渠道账号体系缺「谁在什么时间做了什么」的审计轨迹，属治理与合规缺口。
- **改进**：新增 `admin_audit` 表，记录关键写操作（建号/改密/重置/导出）的操作人、目标、时间。

### M5 · 占位账号污染命名空间 + 文档自相矛盾　🟡 轻中　【已在计划 T3】
- **证据**：`SPEC.md §8` 明确「丢弃 99 个占位」，实际导入 113（含 99 占位），真实号被迫从 `dl_0100` 起；`SPEC / README / VERIFY` 三处账号数互相打架（113 / 114 / 99，见 `VERIFY.md §10.11` 已知差异表）。
- **用户影响**：浪费命名空间、削弱文档可信度。
- **改进**：统一三处口径；占位治理方案（默认隐藏已实施，是否剔除待 B-Q2 拍板）。
