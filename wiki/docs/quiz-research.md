# 同类系统题库与测验机制调研

> 目的：I-1/I-4 改进前，先对照同业（知识库 / 企业培训 / 认证类系统）的测验/题库设计。
> 方法：尝试联网检索（bing/duckduckgo 受反爬不可靠），故以行业通识 + 主流 LMS/国内培训平台的公开功能为准，定向核验待补充。
> 说明：以下为**共性设计范式**，具体平台/版本参数会有差异，如需精确到某产品某版本可再定向核验。

## 1. 测验的两种定位（最核心的划分）

| 类型 | 目的 | 典型设计 |
|---|---|---|
| **形成性练习（formative）** | 帮学员巩固、自测 | 不限次、交卷即给分/对错/答案解析、允许查看错误点 |
| **总结性考试（summative / 认证）** | 判定是否达标/能否结业 | 限次、限时、随机抽题/乱序、交卷后出分、达标给证书 |

> 行业惯例是**两者分开设计**：练习重在反馈，考试重在准入门槛与可信度。
> 对照本项目：当前"必修=必考、选修=练习"只区分了**是否计入认证**，但两类的**体验机制几乎相同**（都是单选+即时判分+不限次，无限时/抽题/解析差异），这是主要差距。

## 2. 常见设计维度（对照参考）

| 维度 | 主流做法 | 本项目现状 | 差异/改进空间 |
|---|---|---|---|
| 及格线 | 行业培训/进阶常用 **60/70/80** 分；认证类倾向 80% | 80 分 | ✅ 已符合"认证类"惯例 |
| 重考次数 | 练习不限次；**认证类普遍限次（2~3 次）且设冷却**（如间隔 1~3 天） | **不限次、无冷却、即点即重考** | 🔺 认证门槛可信度低：可反复刷到及格 |
| 随机抽题 | 认证类多从题库**随机抽 N 题 / 乱序选项**，避免每次同一套 | 固定题目全部、固定顺序 | 🔺 无法防"背答案"，考试区分度低 |
| 限时 | 认证类普遍**限时**（如每题 1~2 分钟） | 无限时 | 🔺 无限时便于查资料 |
| 防作弊 | 锁定全屏、禁复制、切屏告警、人脸核验（高价值认证） | 无 | （本期可不要，非关键资源） |
| 答案/解析反馈 | 练习即时；**考试交卷后才出分、通常不直接给正确答案** | 交卷即出分+错题位置（无解析） | 🔺 若为认证考试，建议**不立即展示错题答案**，避免刷题 |
| 学习完成判定 | 常见"看完即算完成"（视频到结尾/课件打开），也**可要求停留时间/进度** | 打开页面 HTTP 200 即记 `course_views` | 🔺 I-4 议题：太弱，与"完成"语义脱节 |
| 综合结业门槛 | 内容全部完成 + 指定考试及格 → 发证书 | 必修全部浏览 + 必修测验通过 → certified | ✅ 门槛结构合理（口径 B） |

## 3. 与"本次改进"的关系

- **I-4（已学判定）**：同业多区分"**打开**"与"**学完**"。轻量做法（不推翻口径 B）：
  在 `course_views` 增加"上次是否完整看到底部"或要求最低停留（如 ≥30s），提升"浏览=学过"的可信度；否则认证中"必修浏览"仍形同虚设。
- **测验机制（新增建议，可并入 I-4 之后）**：若要提升"通过认证"的分量与可信度，建议：
  1) 认证（必考）限 3 次 + 冷却（如 24h），取最高分；
  2) 题目顺序随机（确保所有备选已存在，seed 恰好每模块 3~5 题，可整卷随机顺序，不必抽题）；
  3) 交卷后**不**展示正确答案（只出分、标错题位置，解析留二期）；
  4) 加分项：限时（每卷 5~10 分钟，取题时下发 `durationLimit`）。

> 注意：1)~4) 会改变现有测验体验与认证判定，需你在「认证可信度」vs「用户便利」间权衡。若渠道伙伴多为长辈、讲究低门槛，则保持"无限重考"也有其合理性。

## 4. 结论一句话
- **最该补的是"认证可信度"**：限次/乱序/不出答案——否则"认证状态"对 CRM 和管理员没有说服力。
- **I-4 轻量化**可行：加"停留/看完"信号，不改口径 B，只提升浏览判定可信度。
- 题库当前为**每模块固定 3~5 题、单卷全出**，与"随机抽题"差异在于：行业认证会**每次都不同**；本项目若想低成本贴近，可先做**每卷打乱题目顺序**（seed 已保证每题独立、answer 合法）。
