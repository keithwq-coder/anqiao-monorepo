# 改进计划（经销商/销售/管理员视角，业务反查）

> 背景：从真实使用者（经销商、内部销售、管理员）角度复审后，发现 5 处最需改进项。
> 状态约定：`[ ]` 待办 / `[x]` 已完成。落地顺序按优先级。

## 优先级与说明

| # | 改进项 | 优先级 | 影响面 |
|---|---|---|---|
| I-1 | 后台与占位账号区分 | P0 | 管理员运营 |
| I-2 | 管理员可重置密码 | P0 | 运营高频痛点 |
| I-3 | 首登引导分步化 | P1 | 经销商体验 |
| I-4 | "已学"判定加强 | P1 | 认证准确性与一致性 |
| I-5 | 登录提示与找回 | P2 | 用户兜底 |

---

### I-1 后台与占位账号区分（P0）—— **已确认方案 A**
**问题**：`seed` 导入 99 个 `dl_0001~dl_0099` 占位账号，`/admin` 列表、统计、CSV 默认全部展示，真实账号被淹没、统计被稀释，且无法区分占位假账号与真实渠道。
**方案**（✅ 已确认 A）：
- [x] A. 列表/统计/导出默认隐藏占位（已实施：is_placeholder + 过滤/统计排除）：新增标识（如 `is_placeholder boolean`），seed 对`dl_0001~0099`标记 true；后台提供"只看真实/只看占位"过滤；统计默认排除占位。
- [ ] B.（已否决）把占位账号从 `users` 剔除，改为"占位不导库、仅保留命名空间"——但与原 `VERIFY` 中"导入 113"的验收冲突，需同步改断言。
- [x] 落点：`src/lib/admin.ts`、`scripts/seed.mjs`、`AdminPanel.tsx`（过滤 UI）、导出接口——已实施。

### I-2 管理员可重置密码（P0）
- **问题**：`POST /api/admin/users` 初始密码只返回一次；忘密码/漏发无admin侧重置入口，只能改库。
- **方案**：
- [x] admin 在学员列表提供"重置密码"（已实施：`/api/admin/users/[id]/reset-password`，重置后旧会话失效）：生成新随机密码（展示一次，复用 `randomPassword`），并置 `must_change_password=true`（可保留首次强制，或仅在原密码仍为初始态时）。
- [x] 落点：reset-password route + AdminPanel 操作列 + 仅 admin——已实施。
- [x] 安全：重置后删除该用户全部会话——已实施。（需评估：`sessions` 表可加 `password_ver` 或在改密时清该用户会话）。

### I-3 首登引导分步化（P1）
- **问题**：`/account` 三块表单（改密、昵称、实名资料）平铺一屏，无引导；经销商有长辈用户，信息密度过高。
- **方案**：
  - [x] 首登仅在 `/account` 高亮"强制改密"步骤（已实施：mustChangePassword 时昵称/资料卡片弱化+标可选），改密成功并用 `.ok` 反馈后，其余条目降级为可折叠/弱化展示；昵称与实名并非常用，放到次级区块。
  - [x] 仪表盘档案横幅（内部=学习档案 / 外部=学习进度）——已实施。："首次请先改密" + 空状态引导（如"从必修模块开始"）。
  - [ ] 落点：`account-form.tsx`、`/` 仪表盘空态。

### I-4 "已学"判定加强（P1）
- **问题**：`recordModuleView` 在 RSC 渲染即记录，`/m/[id]` HTTP 200 即视为"已学"，与真实"浏览"脱节，且认证中"必修模块全部浏览"半形同虚设。
- **方案**（调研见 `docs/quiz-research.md`，轻量落地，不改认证口径 B）：
  - [x] `course_views.has_completed`（migration 002）+ 滚动到底自动标记——已实施。（由前端在课件页滚动到底部时发一次信号置 true）；认证判定仍沿用"出现过即 `viewed`"（口径 B），不因该列改变。
  - [x] 仪表盘状态：已学完 / 已浏览 / 未开始——已实施。：`has_completed=true` 标"已学完"，否则标"已浏览"，避免把打开即完成的弱信号误标为学完。
  - [ ] 落点：`src/lib/certification.ts`（course_views 查询带 has_completed）、`src/app/m/[id]/page.tsx`（滚动到底提交）、`src/app/page.tsx`（状态文案）。

### I-5 登录提示与找回兜底（P2）
- **问题**：登录二选一（用户名/昵称）无提示；忘密码无自助找回 +（I-2 落地前）无 admin 重置。
- **方案**：
  - [x] 登录框提示"用户名或昵称"——已实施。
  - [x] admin 重置作为兜底（I-2 已实施）。；如需自助"忘记密码"（提交 username → 通过预留 phone 发送重置，或由 admin 处理）列入二期。
  - [ ] 落点：`login/page.tsx`、`I-2`。

## 实施顺序建议

2. **I-3 + I-4**（P1，经销商体验与认证准确性）
3. **I-5**（P2，兜底）

- [x] 已实施：三组差异化（types/certification/admin/接口/仪表盘）+ 学习档案替代硬性认证。
