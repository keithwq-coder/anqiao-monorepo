## 二、业务本质（一切设计的前提）

> 来源：README.md、SPEC.md、src/data/*、.reasonix/ppt_v5_dump.txt（产品说明书 v5 原文）

### 2.1 中科安樵是谁

- 中科安樵（苏州）科技有限公司，2023 年成立，**苏州先进技术研究院孵化设立**
- 对外唯一定位口径：**清华同源技术 · 60GHz 毫米波 · 精准健康监测**
- 本质：一家**卖毫米波雷达非接触式健康监测硬件**的智慧养老科技公司，技术锚点 = 引入清华睡眠毫米波雷达技术 + 60GHz 毫米波 + 零摄像头零麦克风

### 2.2 产品体系（四层十款 + 云平台）

v5 说明书定义为"四层十一款"（smart-switch 已下架，现存 10 款）：

### 2.3 卖给谁 / 转化目标（关键）

- **纯 B/G 端获客官网**：目标客户 = 高端外资/民营养老院、政府/社区养老服务中心、基层医疗、大健康美业门店、装企经销商
- **唯一转化目标** = 获取「设备询价 / 方案咨询 / 经销商加盟」线索（SPEC.md 白纸黑字）
- 不做在线交易、不接数据库、不引 UI/动画库、不显示价格
- C 端家庭不是官网直接客户（适老化改造场景面向装企与经销商）

### 2.4 合规是第一性约束（不是附加项）

- 产品本体**无医疗器械注册证**，公司仅持经营备案凭证 → 禁用"医疗级/诊断/治疗/疗效/临床验证/注册证"等词
- **严禁任何准确率/精度百分比**（算法训练值非第三方实测）
- 凯健项目**只能**表述为"建设中示范楼层"，禁止写成已交付/成功案例/客户见证
- 严禁公开渠道政策（返利/区域保护/价格）、严禁案例页/客户 logo 墙/客户评价
- 无数据用 `{{待填}}` 且必须**可见渲染**（浅灰虚线框），不得编造

> 实证：v5 原文的"心率误差<2次/分""9项专利·二类医疗器械资质"、公司介绍 PPT 的全部价格，在官网被 100% 剥离。

## 三、针对性同行调研（同类赛道）

### 3.1 国际标杆：Vayyar Care（真正的技术同源 + 同商业模式）

来源：https://vayyar.com.cn/care/b2b/how-it-works/ 、https://docs.vayyar-cloud.smart-altern.de/en/sensors/vayyar/datasheet/

- 与中科安樵**同技术栈**：60GHz 毫米波 MIMO、无摄像头、墙装/顶装、覆盖 16㎡、隐私安全叙事
- 产品页组织：**How it works（技术原理可视化）→ 安装选项（墙装/顶装/干接点）→ 技术特性（表格化 Datasheet）→ 隐私安全 → Demo 申请（非购买）**
- **可借鉴**：① 技术原理可视化（毫米波"看不见"需图示/视频证明）；② 安装条件前置（墙高 1.5–2.5m、覆盖面积）；③ 无摄像头作为核心差异化叙事
- **不可抄**：其"客户证言 / 案例"区块 —— 中科安樵合规禁止案例与客户见证（§7）

### 3.2 国内同行（智康护 / 海曼 / 旷时 / radarcare / 鸿视美达）

- 智康护 XD-FMS50：产品页"产品优势 / 应用场景 / **规格参数表格化**（工作频段、安装方式、测距范围…）"——验证结构化参数表必要
- 海曼 HS2FD、旷时 QH60MI01：**场景化解决方案**（居家/机构/社区）+ 核心优势逐条
- radarcare.me：按"睡眠/跌倒/存在监测 + App + 平台"组织产品，含 FAQ
- **反面教材：旷时科技写"跌倒检出率达 99%以上"** —— 恰是中科安樵的合规红线，本次方案所有参数/FAQ 一律规避百分比与准确率承诺

### 3.3 B2B 产品页 7 区块最佳实践

来源：letsmedia.tw、jiaye.com.tw B2B 产品页设计方法论

买家决策顺序对应的 7 区块：**标题与价值主张 → 解决什么问题 → 规格与参数（表格化）→ 应用情境与案例 → 信任信号 → FAQ → 询盘 CTA**。要点：
- 规格表格化 + 认证 badge（贴规格旁，不藏"关于我们"）
- CTA 多放（标题下、规格旁、中段、底部），用"获取报价"等行动导向文案
- 图片要"真实感"（实拍多角度、应用情境照、操作演示视频）
- 社会认同（中科安樵合规禁止，用"资质/质保三阶段"替代）

> 该 7 区块与本项目"采购决策缺口"高度吻合，是模块设计的外部佐证。

## 四、现状诊断（结合业务的采购决策缺口）

### 4.1 当前产品页（src/app/products/[slug]/page.tsx，149 行）

四段线性结构：图区（图片纵向堆叠）→ 型号/名称/定位/卖点/场景标签/获取报价 → 技术参数（纯文本）→ 适用客户（纯文本）→ 质保（10 款完全相同）。**无任何客户端交互组件**。

### 4.2 缺失的采购决策信息（按业务重要性）

| 缺口 | 采购影响 | 现状 |
|---|---|---|
| 图片画廊（主图+缩略图+细节/安装图） | 5 款仅一张白底三视图，说服力弱 | 无 |
| **视频演示** | 毫米波"看不见"，极度依赖视频证明有效性 | 无 |
| **文档下载**（说明书/彩页/检测报告 PDF） | 机构需带 PDF 回内部走招标评审 | 无 |
| **FAQ**（误报？隐私？安装条件？断网？辐射？） | 高频疑虑无预解答，拦在询盘前 | 无 |
| 结构化参数表（分组键值） | 纯文本无法横向比对多款 | 纯文本 |
| 相关产品推荐（互补对） | SH100 用户看不到 BH100 | 无 |
| Tab/锚点导航 | 内容增多后无法跳转 | 线性 |

### 4.3 补充的业务级缺口（提案新增，上一版未覆盖）

1. **房间级部署点位维度**：现有 `scenes` 存的是客户类型标签（养老机构/社区居家），但产品真实价值在**物理点位**（卧室/卫浴/客厅/护理站）。建议新增 `deployment` 字段区分。
2. **硬件 ↔ 安守护平台关系可视化**：平台是锁客支点，但在产品列表里只是第 10 张平级卡片，未体现中枢地位。
3. **产品 ↔ 解决方案反向链接**：`/solutions` 的 devices 是纯文本字符串非链接；产品页也缺"本产品出现在哪些方案"入口。两页之间是断的。
4. **质保三阶段复用**：`/about` 有"7日验货/15日换新/24月质保"三阶段表，产品页只有一句话，强信任素材被浪费。

## 五、方案：产品网页组（7 Tab 模块）

> 形态对标 Epson/Canon 的"产品网页组" + Vayyar 的技术原理可视化；**内核全部锚定中科安樵业务**。

顶部粘性 Tab 导航，7 个内容区。无数据的 Tab 自动隐藏（向后兼容）。

| Tab | 业务目的 | 内容 | 合规注意 |
|---|---|---|---|
| **概览** | 三秒说清"是什么+对我有什么用" | 主图+缩略图画廊、型号/名称/一句话定位、核心卖点、场景标签、部署点位、**获取报价 CTA**（带 slug 预填归因） | CTA 必含，不写价格 |
| **功能亮点** | 从"参数罗列"转"痛点→能力→价值" | 图文卡片网格，按房间点位配图（非纯 `<li>` 列表） | 不含禁用词/百分比 |
| **技术规格** | 工程师可快速比对 | 结构化参数表（探测原理/通信方式/安装方式/电源 分组键值） | 用 v5 依据，无训练值% |
| **视频** | 证明"看不见的毫米波" | 产品介绍/安装演示/场景实拍（本地 MP4 或嵌入） | 不涉及医疗宣称 |
| **文档下载** | 供机构走招标内部评审 | 说明书/彩页/检测报告 PDF | 检测报告不含准确率数字 |
| **FAQ** | 打消采购前疑虑 | 误报？隐私？安装条件？断网？辐射安全？（3–5 条） | 不承诺疗效/急救 |
| **相关产品** | 发现互补品 + 平台中枢 | 互补对 SH100↔BH100、A100↔ZQ-50；硬件↔安守护平台可视化；反向链接 /solutions | 平台中枢可视化 |

## 六、SPEC 修订提案（对 §5.3 的具体修改）

### 6.1 现有 §5.3 约束（待修订）

当前 SPEC §5.3 定义产品详情页统一模板：产品图+信息区 / 技术参数 / 适用客户 / 质保说明。需扩展为"Tab 导航 + 7 模块"，并新增数据字段。

### 6.2 数据结构扩展（src/data/products.ts，向后兼容）

```typescript
// 新增类型
export type ProductSpecGroup = {
  groupName: string;                              // 如"探测参数"
  items: { label: string; value: string }[];     // 键值对
};
export type ProductVideo = {
  title: string;
  url: string;                                    // 本地路径或嵌入URL
  type: "intro" | "installation" | "scenario";
};
export type ProductDocument = {
  title: string;
  url: string;                                    // PDF 路径
  type: "manual" | "brochure" | "certificate";
};
export type ProductFAQ = { question: string; answer: string };

// Product 类型扩展（全部可选）
export type Product = {
  // ...现有字段保留...
  deployment?: string[];        // 房间级点位：卧室/卫浴/客厅/护理站（区别于 scenes 客户标签）
  specGroups?: ProductSpecGroup[];   // 优先于 spec 纯文本
  videos?: ProductVideo[];
  documents?: ProductDocument[];
  faqs?: ProductFAQ[];
  relatedSlugs?: string[];      // 互补产品 slug（SH100↔BH100 等）
  isPlatform?: boolean;         // 安守护平台中枢标记
};
```

### 6.3 向后兼容规则

- 所有新字段可选；缺字段时对应 Tab 自动隐藏，不影响现有展示
- `spec` 纯文本保留为兜底（specGroups 存在时优先渲染表格）
- 图片仍硬编码于 `images`，不接 CMS

### 6.4 跨页联动（补业务缺口）

- `relatedSlugs` 驱动"相关产品"Tab，并反向在 `/solutions` 的 devices 上生成链接
- `isPlatform=true` 的产品在列表中标注"云平台中枢"，并在相关产品区可视化"硬件接入平台"
