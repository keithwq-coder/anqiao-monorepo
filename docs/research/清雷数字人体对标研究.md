# 清雷数字人体对标研究

> 目标：对标清雷科技等优秀养老/医疗「数字人体」产品，研究数字人体的**视觉呈现、3D/医学解剖表达、健康数据交互、科技感设计语言**，沉淀可落地到 `anqiao-dashboard` 与 `suqian-dashboard` 的设计结论。
>
> **范围**：仅研究、不改代码。每条关键结论标明【事实】或【设计推断】，并附来源 URL。
>
> 日期：2026-09-25 ｜ 落点目录：`docs/research/`（原 `docs/` 为空、无已有 research 约定，故新建此目录）

## 0. 结论速览（给实现的一个图）

对 two dashboards 最要紧的四条：

1. **数字人体 =「医学可感知的动态人体」**：在现有 `MedicalHologramFigure.vue` 的全息人形之上，补上「器官/系统可点选 + 对应实时波形」的交互闭环（对标清雷数字化中心的「点选查健康」）。
2. **生命体征要「动」且可追踪**：心率/呼吸/呼吸异常/跌倒风险做成清雷式的可视化中心视图（需关注名单、睡眠排行、跌倒风险排行、呼吸异常排行），替代/增强现有三大排行榜与床位矩阵。
3. **「一屏统管 + 主动告警」信息层级**：长者名单 → 设备报警 → 健康指标三级组织（清雷「一屏统管」），对应现有 全域态势/孪生 页的信息架构。
4. **医学严肃性 > 装饰性**：科技感语言沿用现有 HUD 体系即可，重点是把「拟答案、炫彩」降为「可判读、可回溯」，增加医学参考色阶（绿色/黄/橙/红分级）与单位、参考区间、时间戳。

## 二、清雷科技：产品与「数字人体」形态（事实）

### 2.1 公司定位【事实】
- 北京清雷科技有限公司，2019-09-11 成立，法定代表人生丁玉国，总部北京海淀，注册资本 5500 万元；清华大学技术孵化、核心团队来自清华，近 20 年毫米波雷达研发积淀；国家高新技术企业，国内**首家**基于毫米波雷达取得**二类医疗器械注册证**的企业。（S1、百度百科快照经 S3）
- 自我定位：全球领先的医疗级无接触健康监测解决方案提供商、清华科技成果转化的 AI 医疗企业。（S1）

### 2.2 产品矩阵【事实】
- **毫米波雷达生命体征监测仪**：非接触式，穿透衣被，实时捕捉**心率、呼吸（频率与模态）**、体动。（S1、S3）
- **智能跌倒检测仪**：卫生间等场景 27 种姿态跌倒识别。（S3）
- **贝加安®智慧养老系统**：SaaS 后端管理，承载告警、统计、报表。（S1、S3）
- **数字医养可视化中心**：触屏一体机（案例称「触屏电脑一体机」），全院长者健康数据可视化，「点击、滑动即可查看全院长者健康状况，交互性强、科技感十足」。（S3，2023-10-12）
- **智慧养老大屏**：面向照护者/运营者的机构大屏，「一屏统管：整合长者名单、设备报警、健康指标等模块」。（S3，2025-07-02）
- **数字健康画像 / 多维度健康画像**：体征趋势分析 + 周期性报告，构建个性化健康档案。（S3，2025-07-02）
- **清雷健康 App / 小程序**：面向长者的实时睡眠与体征监测、异常告警。（S2、S3）

### 2.3 可视化中心的「数字人体」呈现（事实+推断）
【事实】数字化中心首页展示健康概览：需关注长者名单、睡眠质量排行、跌倒风险排行、呼吸异常排行，并提供数据分析与主动告警；演示向观众展示了「手指在触摸屏点击、滑动看健康」的高交互。（S3）
【设计推断】这正是「数字人体」在此类产品的真实形态：**并非医学解剖级 3D 身体，而是「以人为中心的健康数据聚合体」**——人体/床位作为锚点，生命体征以实时波形、等级排行、异常标记呈现，便于照护者快速定位与响应。

### 2.4 数据与技术底座（事实）
- 院内脱敏临床数据超 15 万例；院外真实世界连续监测数据超 7500 万小时（长期表述为「核心资产是数据与不断迭代的 AI 疾病模型」）。（S3，丁玉国访谈快照）
- 官网口径：50000 例医疗级临床数据 + 5000 万小时真实世界数据；多病种垂直 AI 模型。（S1）
- 已在全国 800 余家养老机构运行（某案例语）。（S3，2025-08-12）
- 关键产品诠释：**「刚刚患者起床/离床过久 / 心动过速过缓 / 呼吸暂停过速」等告警驱动服务**。（S3）

## 三、对标参考：数坤科技「数字人体」（事实）

- 数坤科技自研「数字人体」AI 技术平台，定位「医疗健康世界的大模型」，历经 1.0→4.0；配套「数坤坤」医疗垂类大模型（解析影像、理解文本、掌握诊疗逻辑并具实战经验），延续到「数字医生」整体解决方案。（S4）
- 与清雷的差异：数坤面向**医学影像/AI 辅助诊疗**（疾病筛查、结构化报告），清雷面向**养老/医康养的连续生命体征监测**。两者共同的「数字人体」内核是**用连续、多维数据构建个体化的健康数字镜像**。（设计推断）

> 设计启示：把「数字人体」理解为「个体健康数据镜像」，而非必须上医学解剖 3D——这是两个标杆产品的共同底盘。

## 五、对标结论与设计原则（含事实/推断标注）

### 5.1 数字人体的视觉呈现【推断，源于 S3 事实】
- 结论：养老/医疗「数字人体」应做成**「锚定个体、直读数据」的镜像**，观众先看到人/床位，再看其生命体征，而非先看到炫酷身体模型。
- 建议抽象层级（由低到高可切换）：全息人形 → 系统/器官层（心、肺、脑、循环）→ 指标层（实时波形 + 数值 + 参考区间 + 趋势）。
- 冗余度控制：身体模型只作「定位锚」，强调度高的是波形与数值，避免背景盖过数据。

### 5.2 3D / 医学解剖表达【推断；解剖结构参考现有组件】
- 不建议上重 3D 引擎/解剖高清贴图（医疗 dashboard 读者是照护者/运营者，非医学院用户），**证据：清雷/数坤都未把解剖 3D 作为主交互**（S3、S4）。
- 现有 `MedicalHologramFigure` 已覆盖满意：**淡描骨架+器官示意+辉光**即可传达「医学人体感」。升级方向（可选，非必须）：
  - 器官/系统可点选，选中后该器官「高亮 + 弹出对应波形/数值」（心肺呼吸联动、脑区脑电示意、血管血流动画）。
  - 增加轮廓「系统图例开关」（心脏/肺/骨骼/血管/脑）。
  - 告警时对应部位变绯红 + 冲击波（现状全局 `alert` 已有雏形，可下钻到部位级）。

### 5.3 健康数据交互【推断，源于 S3 事实】
- 对齐清雷数字化中心「点击、滑动查看全院长者健康」→ 加一条**从全景→个人画像的连续下钻动线**：
  双向看板（机构排行/需关注名单）→ 床头矩阵 → 个人全息画像（现状 has `ScreenProfile/Ltci`）→ 单系统波形下钻。
- 信息三级组织「一屏统管」：①长者/床位名单（谁要关注）②设备/告警（发生了什么、在哪台设备）③健康指标（趋势如何）。（S3 一屏统管）
- 告警语义对齐清雷进化清单：呼吸暂停/过速、心动过速/过缓、离床过久、跌倒（多姿态）。（S3）目前 dashboard 已有心率/呼吸/体温字节与文化；建议把呼吸模态、离床时长、跌倒姿态纳入统一告警字典。
- 可回溯：每条告警带**时间戳 + 原始波形段回放 + 处置状态**（对照 S3「完整、准确的体征数据档案」）。

### 5.4 科技感设计语言【推断；现有体系已高度一致】
- 现有 HUD/深空/青绿辉光是同生态的科技感语言，**与标杆一致，无需推翻**；只需「回收」：减少纯装饰闪烁，把动效留给「体征运动」（心跳/呼吸）与「告警」两类语义事件。
- 增加**医学分级色阶**为全局语义（正常=绿 / 关注=琥珀 / 异常=绯红），并统一用于波形线段、排行箭头、告警徽标（现状已部分具备，建议规格化为 token）。
- 数值均为「数值+单位+参考区间+时间戳」，数字字体（Orbitron/Share Tech Mono）保留，单色保证可读性。
- 无障碍：保留 `prefers-reduced-motion` 弱化（现有 `MedicalHologramFigure` 与 global.css 已做，继续保持）。
